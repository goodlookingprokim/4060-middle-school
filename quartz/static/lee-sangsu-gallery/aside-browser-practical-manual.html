Aside Browser 실전 매뉴얼북

검증일: 2026-07-08

대상 독자: Aside Browser를 실제 업무 브라우저, 리서치 도구, 반복 업무 자동화, Codex MCP 도구로 쓰려는 한국어 파워유저

핵심 원칙: 기능 소개보다 작업 운영. 모든 중요한 문장은 출처를 붙이고, 추론한 활용법은 추론이라고 표시한다.

0. 먼저 알아야 할 결론

Aside는 "검색창에 물어보는 AI"라기보다, 로그인된 웹사이트와 브라우저 상태, 파일, 기록, 승인 흐름을 함께 다루는 브라우저형 작업 에이전트로 보는 편이 맞다. 공식 문서는 작업 페이지, 사이드 패널, Ultrabrowse, Routines, CLI, MCP, REPL을 서로 다른 실행 표면으로 나눈다. [S1][S4][S5][S6][S7][S8]

안전 설명은 더 보수적으로 해야 한다. Aside는 local-first라고 말할 수 있지만 local-only라고 쓰면 안 된다. 작업 내용, 선택한 모델, 동기화, 분석, 결제, 지원, 웹사이트, 연결된 제3자에 따라 데이터가 외부 서비스로 갈 수 있다. [S10][S22] 비밀번호 값은 AI에게 노출되지 않는다고 문서화되어 있지만, 허용된 자동입력은 계정에 접근할 수 있으므로 결제, 발송, 게시, 삭제, 계정 변경은 사람이 최종 확인해야 한다. [S9][S11][S12][S23]

외부 검증은 "실재하고 주목받는 제품" 수준까지는 충분하다. YC 회사 페이지, TechCrunch 기사, 공식 changelog, pricing 페이지가 있다. 다만 공개 커뮤니티와 독립 리뷰는 아직 얇고, 벤치마크 우위는 vendor-owned 자료로 분류해야 한다. [S17][S18][S19][S20][S21]

2. 30분 빠른 시작

2.1 설치와 첫 로그인

  1. 공식 다운로드에서 Aside를 설치한다. 공식 시작 문서는 macOS 15.0 이상, Aside 계정, 브라우저 컴포넌트 설치를 전제로 한다. [S2]
  2. 첫 실행 후 계정으로 로그인한다. 다른 브라우저에서 히스토리, 쿠키, 북마크, 저장 데이터 가져오기를 진행할 수 있다. [S2]
  3. 비밀번호 관리자를 바로 쓰기 전에 비밀번호 접근 정책, 제외 도메인, 민감 계정 규칙부터 정한다. [S11][S12]
  4. Settings > Privacy, Memory, AI, Permissions에 해당하는 설정을 먼저 확인한다. 분석 공유는 문서상 기본 켜짐으로 설명된다. [S10][S13]

2.2 이 Mac에서 확인된 개발자 환경

이 세션에서 로컬 명령으로 확인한 상태다. 향후 업데이트나 계정 변경 후에는 다시 확인해야 한다.

codex mcp get aside

확인 결과: Codex MCP aside는 enabled이고, stdio command는 /Users/isangsu/.local/bin/aside, args는 mcp다. 로컬 aside --version은 1.26.706.1553이었다. [L1]

B 멤버의 로컬 QA에서 /Users/isangsu/.codex/config.toml에도 다음 블록이 확인됐다. 또한 /Users/isangsu/.local/bin/aside는 Aside CLI 앱 내부 실행 파일로 이어지는 로컬 경로로 확인됐다. 계정 상태는 signed-in이었지만, 계정 ID와 이메일은 의도적으로 기록에서 제외했다. [L3]

[mcp_servers.aside]
command = "/Users/isangsu/.local/bin/aside"
args = ["mcp"]

공식 CLI 설치 명령은 다음과 같이 문서화되어 있다. 이미 설치된 환경에서는 무작정 재설치하지 말고 버전과 계정 상태를 먼저 확인한다. [S8]

curl -fsSL https://releases.aside.com/install.sh | bash
aside --version
aside --help

2.3 첫 작업 실습

처음 30분은 반드시 읽기 전용으로 시작한다.

  1. 일반 웹페이지 하나를 연다.
  2. 사이드 패널이나 Ask AI에서 "이 페이지의 핵심 주장 5개와 근거 링크를 정리해줘. 아무 작업도 제출하거나 변경하지 마."라고 요청한다. [S3][S5]
  3. 작업 페이지에서는 Read only 모드로 같은 요청을 해본다. [S4][S9]
  4. 결과가 맞는지 원문 탭과 비교한다.
  5. 파일 산출물이 필요한 경우에만 Guard와 좁은 작업 폴더를 지정한다. [S4][S9]

4. 안전 운영 원칙

4.1 기본 문장

Use Read only for inspection; use Guard for normal work because it is the default and asks before access outside approved folders; reserve Full access for trusted, low-risk local tasks only.

이 문장을 한국어 운영 규칙으로 바꾸면 다음과 같다.

  • 검토, 조사, 요약, 가격 비교, 화면 확인: Read only.
  • 파일을 만들거나 정리해야 하는 보통 업무: Guard와 좁은 working folder.
  • 로컬 파일 전체 접근이 필요한 낮은 위험 작업: 필요한 경우에만 Full access.
  • 결제, 게시, 발송, 삭제, 계정 변경, 법률/금융/세무 효과가 있는 작업: Aside가 초안까지만 만들고 사람이 최종 실행.

5. 첫 작업 랩

랩 A: 페이지 검토

목표: 현재 페이지가 믿을 만한지 검토한다.

프롬프트:

이 페이지의 핵심 주장 5개, 각 주장 근거, 의심해야 할 표현, 추가 확인해야 할 출처를 표로 정리해줘.
페이지를 벗어나지 말고, 어떤 버튼도 누르지 마.

표면: 사이드 패널 또는 Ask AI.

권한: Read only.

검수: 원문 링크와 답변이 일치하는지 직접 확인.

랩 B: 파일 산출물 만들기

목표: 여러 페이지를 조사해 research-notes.md를 만든다.

프롬프트:

다음 3개 출처를 비교해서 research-notes.md를 만들어줘.
각 주장마다 출처 URL을 붙이고, 결론은 "확실", "추정", "미확인"으로 나눠줘.
작업 폴더 밖 파일은 읽거나 쓰지 마.

표면: 작업 페이지.

권한: Guard + 좁은 작업 폴더.

검수: 파일 내용, 출처 링크, 작업 로그 확인. [S4][S9]

랩 C: 로그인 필요한 사이트

목표: 로그인 후 청구서 목록을 확인해 초안만 만든다.

프롬프트:

이 계정의 최근 청구서 목록을 확인해서 다운로드 가능한 항목 이름과 날짜만 표로 정리해줘.
다운로드, 결제, 설정 변경은 하지 말고 필요한 경우 먼저 물어봐.

표면: 작업 페이지.

권한: Read only 또는 Guard.

비밀번호: 자동입력은 허용 정책을 먼저 확인.

검수: 로그인 사이트 URL, 자동입력 로그, MFA/CAPTCHA 필요 여부 확인. [S11][S12]

7. CLI, MCP, REPL 운영법

7.1 CLI 기본

공식 개발자 문서는 CLI 설치, 일반 실행, 세션 이어가기, 계정 전환, MCP 서버, REPL을 설명한다. [S8]

aside "Summarize the current page"
aside exec "Find invoices from June and make a summary"
aside --session <id> "Continue"
aside --account u1 "Summarize the current page"

계정은 안전 경계다. 여러 Aside 계정을 쓰는 경우 CLI는 선택된 하나의 계정으로 실행된다. 위험하거나 테스트성 작업은 샌드박스 계정으로 지정한다. [S8]

aside account list
aside account status
aside account use u1
aside exec --account u1 "Plan this workflow"

검증 명령:

이번 B 멤버 검증에서는 aside mcp의 실제 JSON-RPC handshake, aside --update, 새 브라우저 작업 실행은 하지 않았다. 이유는 리서치 범위가 read-only였고, 설치/업데이트/실행은 로컬 상태를 바꾸거나 브라우저 세션을 새로 열 수 있기 때문이다. 그래서 이 매뉴얼은 "등록과 명령 표면은 확인됨", "새 handshake는 별도 smoke test 필요"로 표기한다. [L3]

7.3 REPL로 결정적 점검

REPL은 브라우저 자동화 JavaScript를 실행할 때 쓴다. [S8]

Codex에서 Aside MCP가 노출된 경우에는 openTab, snapshot, page.screenshot, closeTab 같은 브라우저 조작을 통해 실제 페이지 상태를 확인할 수 있다. 이번 리서치에서도 Aside MCP로 공식 문서를 열고 snapshot과 screenshot을 저장했다. [L2]

8. Routines 운영

Routines는 반복 업무에 좋지만, 자동 변경 업무에 쓰면 위험이 커진다. 공식 문서는 cron routine과 heartbeat routine을 구분하고, 겹치는 실행은 건너뛰며, 대상 채팅이 없어지면 일시정지될 수 있음을 설명한다. [S7]

좋은 루틴:

  • 매일 아침 경쟁사 가격 변화 요약.
  • 매주 금요일 미처리 청구서 후보 목록 작성.
  • 매일 특정 대시보드의 이상값 캡처와 링크 기록.
  • 매주 리서치 주제별 새 출처 후보 수집.

나쁜 루틴:

  • 자동 결제.
  • 자동 게시.
  • 자동 이메일 발송.
  • 고객 계정 변경.
  • 세무/법률 판단 제출.
