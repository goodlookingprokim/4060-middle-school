깃허브 명령어,
단어 하나씩 뜯어보기

명령어를 통째로 외우지 마세요. 단어 하나하나가 무슨 뜻인지 알면, 조합은 저절로 이해됩니다. 칠판에 하나씩 뜯어서 적어드릴게요.

비유부터 clone checkout -b add commit push pull status / branch 충돌 해결 전체 요약

먼저, 명령어의 구조부터

모든 깃 명령어는 "도구 + 할 일 + 옵션 + 대상" 순서로 조립된 하나의 문장입니다. 예를 들어 git commit -m "메시지"를 우리말 문장으로 바꾸면 이렇습니다.

영어 단어우리말 뜻역할
git"깃 도구야,"도구 부르기
commit"저장해줘"할 일(동사)
-m"메시지는 바로 적을게"옵션(방식)
"메시지""로그인 화면 완성"대상(내용)

이 문서에서는 색깔로 역할을 구분합니다. ■ 도구 · ■ 동사(할 일) · ■ 옵션 · ■ 대상

STEP 01 · 시작할 때 딱 1번

git clone — "통째로 복사해와"

쉬운 예시: 도서관 책을 복사기로 그대로 복사해서 집에 가져오는 것

git ↓ "깃 도구야"
이 일을 시킬 도구 이름
clone ↓ "복제해줘"
통째로 똑같이 베끼라는 뜻
(주소) ↓ "어디서?"
복사해올 리포의 인터넷 주소
$ git clone https://github.com/팀이름/프로젝트.git
합쳐서 읽으면: "깃 도구야, 이 주소에 있는 공책을 통째로 복사해줘."
실전에서는: 해커톤 첫날, 팀장이 리포 주소를 단톡방에 올리면 팀원 전원이 이 명령어 한 줄만 자기 컴퓨터에서 실행하면 됩니다.
옵션 더 알아보기 (자주 쓰는 2가지)
옵션단어 뜻효과
git clone (주소) 폴더이름맨 뒤에 이름 하나 더복사할 폴더 이름을 내가 원하는 대로 지정
-b 브랜치이름b = branch(노트)복사할 때 특정 노트를 처음부터 펼쳐놓고 시작
STEP 02 · 작업 시작할 때마다

git checkout -b — "새 노트 꺼내서 바로 펼치기"

쉬운 예시: 서랍에서 새 공책을 꺼내 표지에 이름 쓰고, 바로 펼쳐놓는 것

git ↓ 깃 도구야
checkout ↓ "이동해줘"
펼쳐진 노트를 바꾸는 것
-b ↓ "새로 만들면서"
branch의 b, 없던 노트를 새로 만듦
feature/민수-로그인 ↓ 새 노트의 이름표
$ git checkout -b feature/민수-로그인
합쳐서 읽으면: "깃 도구야, '민수-로그인'이라는 이름의 새 노트를 만들고, 그 노트로 바로 이동해줘."
사실 이 명령어는 2가지 일을 합친 단축키예요
따로 하면뜻
git branch feature/민수-로그인노트를 "만들기"만 함 (아직 안 펼침)
git checkout feature/민수-로그인그 노트를 "펼치기"만 함

이 2줄을 한 번에 하는 게 checkout -b입니다. 지금 어떤 노트가 펼쳐져 있는지 궁금하면 git branch로 확인하세요. * 표시가 붙은 게 지금 펼쳐진 노트입니다.

STEP 03 · 작업 중 자주

git add — "장바구니에 담기"

쉬운 예시: 편의점에서 물건 고를 때 계산 전에 장바구니에 먼저 담는 것

git ↓ 깃 도구야
add ↓ "담아줘"
저장 전에 후보로 골라 담기
. ↓ "전부 다"
점(.)은 지금 폴더 안의 전체
$ git add .
합쳐서 읽으면: "깃 도구야, 지금 바뀐 것 전부 다 장바구니에 담아줘."
확인 방법: git status를 치면 빨간 글씨(아직 안 담김)와 초록 글씨(담김)로 구분해서 보여줍니다.
옵션 3가지 비교
명령어단어 뜻효과
git add .. = 전부지금 폴더 안에서 바뀐 것 전부 담기
git add 파일이름.txt파일 이름 직접 지정그 파일 하나만 콕 집어서 담기
git add -A-A = All.과 비슷하지만 삭제한 파일까지 포함해서 담음 (더 안전)
STEP 04 · 작업 중 자주

git commit -m — "계산하고 영수증에 메모 남기기"

쉬운 예시: 게임하다가 "저장하기" 누르고, 저장 파일 이름을 적는 것

git ↓ 깃 도구야
commit ↓ "저장해줘"
장바구니 내용을 실제로 도장 찍기
-m ↓ "메시지는 바로 적을게"
message의 m
"로그인 화면 완성" ↓ 무엇을 했는지
한 줄 메모
$ git commit -m "feat: 로그인 화면 UI 추가"
합쳐서 읽으면: "깃 도구야, 장바구니에 담긴 걸 저장하는데, 메시지는 '로그인 화면 UI 추가'라고 적어줘."
나쁜 예 vs 좋은 예:
❌ git commit -m "수정" — 나중에 뭘 고쳤는지 알 수 없음
✅ git commit -m "로그인 버튼 클릭 시 오류 수정" — 한눈에 이해됨
옵션 더 알아보기
명령어단어 뜻주의할 점
git commit (옵션 없이)메시지를 나중에 씀메모장 화면이 뜨는데 초보자는 헷갈림 → -m 추천
git commit -am "메시지"-a = add 생략이미 저장했던 적 있는 파일만 add 없이 바로 커밋. 새 파일은 안 잡힘
STEP 05 · 다 됐을 때

git push -u origin — "인터넷에 업로드하고 주소 기억시키기"

쉬운 예시: 핸드폰 사진을 구글 드라이브에 업로드하는 것

git ↓ 깃 도구야
push ↓ "밀어 올려줘"
내 노트를 인터넷 서버로
-u ↓ "연결을 기억해줘"
upstream의 u
origin ↓ "우리 팀 리포"
자동으로 붙는 별명
feature/민수-로그인 ↓ 올릴 노트 이름
$ git push -u origin feature/민수-로그인
합쳐서 읽으면: "깃 도구야, '민수-로그인' 노트를 우리 팀 리포에 올리는데, 이 연결을 다음에도 기억해줘."
-u의 진짜 쓸모: 택배 주소를 처음 한 번 저장해두면 다음부턴 안 써도 되는 것처럼, -u를 한 번 해두면 다음부턴 그냥 git push만 쳐도 알아서 같은 곳으로 올라갑니다.
STEP 06 · 작업 시작 전, 매일

git pull origin main — "최신 내용 당겨오기"

쉬운 예시: 단체 카톡방에서 안 읽은 메시지 새로고침하는 것

git ↓ 깃 도구야
pull ↓ "당겨와줘"
push의 반대, 서버 → 내 컴퓨터
origin ↓ 우리 팀 리포에서
main ↓ 정본 공책 기준으로
$ git pull origin main
합쳐서 읽으면: "깃 도구야, 우리 팀 리포의 정본 공책(main)에 새로 추가된 내용을 내 컴퓨터로 가져와줘."
왜 자주 해야 하냐면: 내가 작업하는 동안 다른 팀원이 먼저 merge 했을 수 있습니다. 이걸 안 가져오고 계속 작업하면 나중에 충돌이 커집니다. 하루 시작 전, push 하기 직전 두 타이밍에 꼭 pull하세요.
확인용 · 언제든

git status / git branch — "지금 상태 물어보기"

쉬운 예시: 장바구니에 뭐가 담겼는지, 지금 어느 노트가 펼쳐져 있는지 확인하는 것

git ↓ 깃 도구야
status ↓ "지금 상태 보여줘"
담긴 것 / 안 담긴 것 구분
$ git status
git ↓ 깃 도구야
branch ↓ "노트 목록 보여줘"
*표시 = 지금 펼친 노트
$ git branch
가끔 만나는 상황

충돌(conflict) — "누구 걸 남길지 정해줘"

쉬운 예시: 두 사람이 같은 문장을 서로 다르게 고쳐놔서, 어느 걸 남길지 사람이 직접 정해야 하는 상황

이건 새 명령어가 아니라, git pull 하다가 화면에 나타나는 표시입니다. 이 표시 자체를 뜯어봅시다.

<<<<<<< HEAD 민수가 쓴 코드 ======= 영희가 쓴 코드 >>>>>>> feature/영희-메인화면
<<<<<<< HEAD ↓ "여기부터"
내가 지금 갖고 있던 코드 시작
======= ↓ "여기가 경계선"
내 코드와 상대 코드를 나누는 선
>>>>>>> (브랜치명) ↓ "여기까지"
상대방 코드가 어디서 끝나는지 + 누구 노트인지
이건 고장이 아닙니다. 컴퓨터가 "둘 다 코드가 있는데 뭘 남겨야 할지 모르겠어요"라고 정직하게 물어보는 것뿐입니다.

해결 순서: 남길 코드를 정하고, 표시 3줄(<<<<<<<, =======, >>>>>>>)을 직접 지운 뒤 저장합니다.

$ git add .
$ git commit -m "충돌 해결: 로그인과 메인화면 병합"
$ git push
팁: 커밋 메시지에 "충돌 해결"이라고 꼭 써두세요. 나중에 기록 볼 때 어디서 문제가 있었는지 바로 알 수 있습니다.

칠판 지우기 전, 한 장 정리

동사뜻비유
clone통째로 복사해오기도서관 책 복사기로 복사
checkout -b새 노트 만들고 펼치기새 공책 꺼내서 이름 쓰기
add저장 후보로 담기편의점 장바구니 담기
commit -m실제 저장 + 한 줄 메모게임 저장하고 파일명 적기
push -u인터넷에 올리고 주소 기억드라이브 업로드 + 주소 저장
pull최신 내용 당겨오기단톡방 새로고침
status / branch지금 상태 확인장바구니·펼친 노트 확인
# 처음 한 번만
git clone (리포 주소)

# 작업 시작할 때마다
git checkout main
git pull origin main
git checkout -b feature/내이름-작업내용

# 작업 중 자주
git add .
git commit -m "무엇을 했는지 한 줄"

# 다 됐을 때
git push -u origin feature/내이름-작업내용

딱 하나만 기억하세요 — add는 장바구니 담기, commit은 계산(저장), push는 업로드, pull은 새로고침. 이 4개 동사만 몸에 익으면, 옵션은 필요할 때 이 칠판을 다시 보면서 찾아 쓰시면 됩니다.
