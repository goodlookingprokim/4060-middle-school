사람은 더 앞단에서 방향과 경계를 설계한다

이 강의의 공통 주제는 AI가 답을 주는 도구에서, 컴퓨터 안에서 실제 작업을 수행하고 여러 도구를 연결해 결과물을 배포하는 작업자로 이동하고 있다는 것입니다. Omarchy는 운영 환경, Spark Beat는 제품화, HyperFrames는 반복 가능한 영상 제작으로 같은 변화를 보여줍니다.

완전 자동화가 결론은 아닙니다. 사람이 해야 할 핵심 역할은 무엇을 만들지 정하고, 바꾸면 안 되는 것을 제한하고, 계획을 승인하고, 독립적으로 실패를 검토하며, 최종 결과가 실제 현장에서 쓸 만한지 판단하는 일로 이동합니다.

ISO와 USB 설치

ISO를 USB에 담고 PC의 부팅 순서를 바꿔 설치합니다. 기존 Windows PC에 직접 설치하면 디스크가 지워질 수 있다는 경고가 반복됩니다.

하드웨어 해석의 경계

2011년형 노트북 사례와 M2 MacBook 사례가 언급되지만, M2는 가상 머신 설치였습니다. 베어메탈 호환성으로 확대 해석하면 안 됩니다.

이름과 제작자

화면에서 DHH가 제작자로 소개됩니다. “오마카세식 사전 선택과 Arch Linux의 결합”이라는 어원은 발표자의 설명입니다.

왜 지금 “에이전트 OS”인가

CLI 에이전트가 로컬 파일을 직접 다루는 시대에, macOS와 Windows가 아닌 에이전트 중심 기본 환경이 필요하다는 문제의식을 제시합니다.

앱에서 OS로

여러 터미널과 병렬 에이전트를 띄울수록 기존 데스크톱 환경이 무거워지고 조작 방식도 파편화된다는 경험에서 출발합니다.

사전 선택된 가벼운 환경

좋은 도구와 설정을 제작자가 미리 묶어 Linux 구성의 선택·충돌 비용을 줄인다는 설명입니다. 48초 설치 주장은 강의에서 측정하지 않았습니다.

좌표 추정과 네이티브 제어

화면 캡처 후 좌표를 찾는 Computer Use보다, OS 안에서 더 직접적으로 동작하는 환경이 오류와 비용을 줄일 수 있다고 해석합니다.

“에이전트가 이 안에서 산다”

에이전트가 컴퓨터 바깥의 도구가 아니라 파일·브라우저·터미널·창을 다루는 기본 구성원이 된다는 비유입니다.

A. 에이전트 작업 환경을 시험할 때

  2. 바로 코딩하지 말고 계획 설명과 사용자 승인을 사이에 둡니다.
