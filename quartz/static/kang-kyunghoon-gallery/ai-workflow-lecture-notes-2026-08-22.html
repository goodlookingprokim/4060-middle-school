clone·branch·commit·push·merge

팀원은 main을 직접 수정하지 않고 기능 브랜치에서 작업한 뒤 PR로 검토와 병합을 요청합니다.

  • 리더가 저장소와 README를 만들고 팀원을 초대합니다.
  • 팀원은 clone 후 최신 main에서 기능 브랜치를 만듭니다.
  • 변경을 commit·push하고 PR을 열어 검토를 요청합니다.
  • 관리자는 승인된 변경을 merge하고 충돌이 나면 유지할 내용을 판단합니다.
  • 다음 작업 전 최신 main을 받아 GitHub를 팀의 최신 통합본으로 유지합니다.
