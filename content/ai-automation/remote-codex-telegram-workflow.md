# Codex 프로젝트를 Telegram으로 원격 이어가는 워크플로우

로컬 컴퓨터에서 진행하던 작업을 외부에서도 자연스럽게 이어가고 싶을 때가 있습니다.  
이번에 정리한 방식은 **Codex는 로컬에서 돌리고, Telegram은 원격 브릿지처럼 쓰는 구조**입니다.

핵심은 단순합니다.

- 로컬 컴퓨터는 실제 작업 본체
- Telegram 봇은 원격 지시 창구
- 복잡한 마무리는 다시 로컬에서 확인

## 역할 분리

### 로컬 컴퓨터

여기서 실제 프로젝트 파일, git, 테스트, 빌드가 돌아갑니다.

### Todooly

`@todooly_bot`은 상시 비서가 아니라 **필요할 때만 켜는 Codex 브릿지 봇**으로 두는 게 가장 깔끔했습니다.

이 역할에 집중하면 장점이 분명합니다.

- 외부에서 진행 상황 확인 가능
- `/resume` 같은 흐름으로 이어가기 쉬움
- 작은 수정이나 요약 요청에 강함
- 평소에는 조용해도 이상하지 않음

### Totobot

반대로 일정, 메일, 리마인드 같은 개인 비서 역할은 따로 분리해두는 편이 덜 헷갈립니다.

## 실제 운영 흐름

1. 컴퓨터 앞에서 프로젝트 시작
2. 필요하면 Todooly 브릿지 실행
3. 외부에서는 Telegram으로 상태 요약, 수정, 다음 작업 요청
4. 중요한 최종 판단은 다시 로컬에서 확인

이렇게 두면 원격 작업이 "모든 걸 다 대신하는 방식"이 아니라, **일을 끊기지 않게 이어주는 방식**으로 정리됩니다.

## 원격에 잘 맞는 작업

- 현재 상태 요약
- 에러 원인 분석
- 작은 코드 수정
- 문서 수정
- 테스트 결과 정리
- 다음 액션 제안

## 원격에 덜 맞는 작업

- 긴 인터랙티브 디버깅
- GUI 조작이 핵심인 작업
- 인증과 승인이 복잡한 작업
- 큰 구조 변경

이런 건 Telegram에서 요약만 받고, 실제 마무리는 로컬에서 보는 게 낫습니다.

## 결론

원격으로 일한다는 건 결국 "밖에서도 모든 걸 다 한다"가 아니라,  
**지금 하던 흐름을 끊기지 않게 이어간다**에 더 가깝습니다.

그 기준으로 보면,  
Codex는 로컬에 두고 Telegram은 가볍게 연결하는 지금 구조가 꽤 균형이 좋습니다.
