# 새 컴퓨터를 받았을 때 무엇부터 깔아야 할지 막막하다면, lazy-starter-kit은 무엇을 줄여줄까

새 노트북이나 새 PC를 받으면 기분은 좋은데, 막상 시작하려면 첫걸음이 꽤 번거롭습니다.

- Git은 어디서 깔지
- Python, Node, Docker는 뭐부터 해야 할지
- 터미널은 왜 남들 화면처럼 안 예쁜지
- Claude Code나 Codex 같은 AI 도구는 또 어디서부터 붙여야 하는지

이런 일은 한 번 할 때는 견딜 만하지만, 컴퓨터를 바꿀 때마다 다시 하면 꽤 피곤합니다. 오늘 글은 바로 그 피곤함을 줄이려는 GitHub 저장소 `lazy-starter-kit`을 4060미들스쿨 눈높이로 풀어본 글입니다.

출처: 이 글은 Heoooooon님의 GitHub 저장소 `lazy-starter-kit`과 그 README를 바탕으로 정리했습니다. 글 하단에 원본 링크를 함께 남겨둡니다.

## 먼저 결론

- `lazy-starter-kit`은 새 컴퓨터를 받을 때 **개발 환경과 AI 코딩 도구 세팅을 한 번에 깔아주는 시작 꾸러미**라고 이해하면 쉽습니다.
- 핵심은 "많이 깔아준다"보다 **반복되는 설치 순서를 줄여주고, 이미 있는 설정을 함부로 덮어쓰지 않게 설계했다**는 점입니다.
- 특히 Claude Code, Codex 같은 AI 코딩 도구를 써보고 싶지만, 그 전에 깔아야 할 것들이 너무 많아 막히는 사람에게 첫 진입 장벽을 낮춰 줍니다.

## 왜 이런 저장소가 필요할까

처음 AI 코딩을 써보려는 사람은 보통 AI보다 설치에서 먼저 지칩니다.

예를 들어 이런 장면이 자주 생깁니다.

- 새 맥북을 샀다
- 유튜브나 블로그를 보고 Claude Code를 써보고 싶다
- 그런데 Git, 터미널, Node, Python, GitHub 로그인부터 먼저 나온다
- 중간에 하나라도 꼬이면 "이건 나랑 안 맞나 보다" 하고 멈춘다

이럴 때 필요한 것은 더 어려운 설명이 아니라, **처음 며칠의 시행착오를 줄여 주는 시작 세트**입니다.

실생활 비유로 바꾸면 이렇습니다.

> 새 집으로 이사했는데, 냉장고만 들여놓는다고 바로 생활이 시작되지는 않습니다. 인터넷, 가스, 식기, 청소도구, 자주 쓰는 컵까지 자리를 잡아야 비로소 살기 편해집니다.

`lazy-starter-kit`은 바로 그 "살기 시작하는 기본 세팅"을 개발 환경 쪽에서 대신해 주는 도구에 가깝습니다.

## lazy-starter-kit은 무엇을 깔아주나

README 기준으로 이 저장소는 새 컴퓨터에 자주 필요한 것을 한 번에 잡아줍니다.

- Git, ripgrep, fzf, bat 같은 기본 CLI 도구
- Node.js, Python, Go, Rust 같은 런타임
- zsh, starship 같은 터미널 환경
- Docker 같은 컨테이너 도구
- Claude Code, Codex, gajae-code, lazycodex 같은 AI 코딩 에이전트

즉, 단순히 "AI 도구 하나"를 설치하는 것이 아니라, **AI 도구가 편하게 돌아갈 작업 환경 전체를 미리 갖춰 주는 방식**입니다.

## 회원분들 기준으로는 무엇이 제일 좋을까

4060미들스쿨 기준으로 이 저장소의 좋은 점은 아래 다섯 가지로 정리할 수 있습니다.

### 1. 새 컴퓨터를 받을 때 어디서부터 시작해야 할지 덜 막막하다

보통 처음에는 "어떤 순서로 깔아야 하지?"가 가장 어렵습니다.

`lazy-starter-kit`은 그 순서를 어느 정도 대신 정해 둔 상태입니다. 그래서 사용자는 하나하나 검색하기보다, 먼저 전체 세팅을 돌리고 그다음 필요한 도구를 써보는 쪽으로 갈 수 있습니다.

즉, 요리 레시피를 처음부터 다시 짜는 대신, 장보기 목록과 조리 순서가 이미 적힌 종이를 받는 것과 비슷합니다.

### 2. 이미 있는 설정을 함부로 덮어쓰지 않으려는 점이 마음이 편하다

초보자가 설치 스크립트를 무서워하는 가장 큰 이유는 이것입니다.

> "이거 실행했다가 내 컴퓨터가 이상해지면 어떡하지?"

README에서 계속 강조하는 부분도 바로 이것입니다.

- 이미 있는 건 건너뛴다
- 여러 번 다시 실행해도 안전하게 설계한다
- 설정 파일도 표시된 블록만 건드린다
- 필요하면 제거 스크립트도 있다

이 말은 결국 "싹 밀고 다시 까는 방식"이 아니라, **있는 집을 최대한 건드리지 않고 필요한 가구만 들이는 방식**에 가깝다는 뜻입니다.

### 3. 회사 PC와 개인 맥북을 같은 감각으로 다루기 쉽다

README를 보면 macOS, Linux, Windows를 따로 안내합니다. 특히 Windows 설명이 자세해서, 회사 PC에서 PowerShell만 열 수 있는 사람도 따라가게 하려는 의도가 보입니다.

이건 실무적으로 꽤 중요합니다.

- 집에서는 맥북
- 회사에서는 윈도우
- 어떤 분은 우분투나 WSL

이렇게 환경이 달라도 "세팅 철학"을 비슷하게 가져가게 해 주기 때문입니다.

### 4. AI 코딩 도구를 쓰기 전 단계의 피로를 줄여준다

요즘은 Claude Code나 Codex에 관심은 있어도, 막상 시작 전에 깔아야 할 것이 많아 중간에 힘이 빠지는 경우가 많습니다.

`lazy-starter-kit`은 이 부분을 꽤 현실적으로 건드립니다.

- 터미널 환경
- Git/GitHub
- 런타임
- AI 에이전트

이 네 가지를 한 흐름으로 묶어두면, 사용자는 "도구 공부"보다 **실제로 첫 결과물을 만들어보는 단계**로 더 빨리 넘어갈 수 있습니다.

### 5. "그냥 한 번 써보는 사람"보다 "앞으로 계속 쓸 사람"에게 더 맞다

이 저장소는 일회성 설치 팁이라기보다, 앞으로도 계속 다시 돌려 쓰는 쪽에 가깝습니다.

- 새 버전 업데이트
- 빠진 도구 점검
- 다시 설치
- 일부만 설치
- 회사용 가볍게 설치

이런 흐름이 준비되어 있어, 한 번 쓰고 끝나는 것이 아니라 **나중에 컴퓨터를 다시 세팅할 때도 같은 길로 들어오게** 해 줍니다.

## 어떤 분에게 특히 잘 맞을까

### 이런 분께 잘 맞습니다

- 새 컴퓨터를 받았을 때 설치 순서부터 막막한 분
- Claude Code, Codex를 써보고 싶은데 준비 단계가 버거운 분
- 회사 PC와 집 PC를 오가며 비슷한 환경을 만들고 싶은 분
- 설치 스크립트는 무섭지만, 그래도 반복 작업은 줄이고 싶은 분

### 이런 경우에는 조금 천천히 보는 편이 낫습니다

- 터미널 자체가 완전히 낯설어서 명령어 복붙도 아직 부담스러운 경우
- 회사 보안 정책이 강해서 스크립트 실행 자체가 어려운 경우
- 지금은 AI 코딩보다 문서 작성이나 이미지 생성에만 관심이 있는 경우

이런 경우에는 바로 전체 세팅을 하기보다, 먼저 "터미널 열기", "GitHub 로그인", "Git이 무엇인지" 정도부터 가볍게 익히는 편이 낫습니다.

## README에서 특히 좋았던 대목

이 저장소는 단순히 "한 줄로 설치됩니다"만 말하지 않고, 초보자가 불안해하는 지점을 계속 설명합니다.

예를 들면 이런 부분입니다.

- 먼저 `dry-run`으로 무엇을 할지 볼 수 있다
- 회사 PC용 가벼운 프로필이 있다
- 이미 있는 설정을 덮어쓰지 않게 한다
- 제거 스크립트가 있다
- 여러 운영체제에서 CI로 설치·검증·제거를 자동 테스트한다

이런 설명은 기술적으로 대단한 말보다, 실제로 시작하려는 사람에게 더 중요한 안심 장치입니다.

## 회원분들 눈높이에서 보면 이렇게 이해하면 된다

조금 단순하게 말하면 이 저장소는 이런 역할입니다.

> "새 컴퓨터를 받았을 때, AI 코딩을 해보기 전에 필요한 준비물을 한 번에 챙겨주는 출발 꾸러미"

그리고 더 쉽게 말하면 이렇습니다.

> 공구함 하나를 사면 망치 하나만 들어 있는 게 아니라, 드라이버와 줄자와 못도 함께 들어 있어야 일을 시작할 수 있는데, `lazy-starter-kit`은 그 공구함에 가깝다.

## 처음 써본다면 이렇게 접근하면 좋다

처음부터 욕심내지 말고, 아래 순서가 가장 편합니다.

1. README를 끝까지 다 읽기보다 `이게 뭔가요?`, `무엇이 깔리나`, `설치해도 안전한가요?` 세 부분부터 본다.
2. 내 컴퓨터가 Windows인지 Mac인지부터 정확히 고른다.
3. 바로 실행하지 말고 먼저 `dry-run`이 되는지 확인한다.
4. 설치가 끝나면 Claude Code나 Codex 중 하나만 먼저 켜 본다.
5. 첫 프롬프트로 작은 결과물 하나를 직접 만들어 본다.

이때 가장 좋은 첫 목표는 거창한 앱보다, "한 파일짜리 작은 웹페이지"처럼 눈으로 바로 확인되는 결과물입니다.

## 바로 써볼 질문

이 저장소를 보고 바로 떠올려볼 질문은 아래 정도면 충분합니다.

```text
나는 지금 Mac과 Windows 중 어디에서 먼저 AI 코딩을 시작하는 게 더 편할까?
```

```text
새 컴퓨터를 받았을 때 Git, Python, Node, Claude Code를 어떤 순서로 준비하면 덜 꼬일까?
```

```text
설치 스크립트를 바로 돌리기 전에 무엇을 먼저 확인하면 안전할까?
```

```text
설치가 끝난 뒤 Claude Code로 가장 먼저 해볼 만한 작은 실습은 무엇일까?
```

좋은 질문의 공통점은 "이 저장소가 멋지다"보다, **내 상황에서 어디부터 시작하면 되는지**를 묻는다는 점입니다.

  <li>처음에는 AI 에이전트 하나만 켜 보고, 첫 결과물 하나를 만드는 데 집중한다.</li>
  <li>설치 자체보다 "설치 후 내가 무엇을 해볼지"를 먼저 정해 두면 훨씬 덜 헤맨다.</li>
</ul>

## 남겨둘 판단

AI 코딩을 시작할 때 가장 큰 장벽은 모델이 아니라, **내 컴퓨터를 일할 수 있는 상태로 만드는 과정**일 때가 많습니다.

`lazy-starter-kit`은 바로 그 준비 과정을 줄이려는 저장소입니다. 그래서 이미 터미널과 개발 환경이 익숙한 사람보다, "새 컴퓨터에서 어디부터 만져야 할지 모르겠다"는 사람에게 더 체감이 큽니다.

오늘 하나만 기억하면 이것이면 충분합니다.

> AI 코딩을 잘하려면 좋은 프롬프트만 필요한 게 아니라, 내 컴퓨터가 덜 꼬이고 덜 불안한 작업 환경이어야 한다.

`lazy-starter-kit`은 그 출발점을 빠르게 잡아주는 쪽에 가까운 도구입니다.
