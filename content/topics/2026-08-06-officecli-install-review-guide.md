# officecli는 오피스 문서를 코드처럼 다루고 싶을 때 어디까지 쓸 만할까

오피스 문서를 다룬다고 하면 보통 Word, Excel, PowerPoint 화면을 먼저 떠올립니다. 그런데 문서를 하나씩 손으로 여는 대신, 명령어로 만들고 고치고 점검하고 싶을 때가 있습니다. `officecli`는 바로 그 지점에서 등장하는 도구입니다.

이번 글은 공식 소개문을 옮겨 적은 정리가 아니라, 실제로 `officecli`를 써서 소개용 PPT를 만들고, 화면을 다시 뽑아 보고, 넘치는 글자를 고쳐 본 경험을 바탕으로 적었습니다. 그래서 “무슨 기능이 있나”보다 “실제로 어디에 좋고, 어디에서 멈칫하는가”를 먼저 보게 될 겁니다.

## 먼저 결론

- `officecli`는 문서를 예쁘게 만드는 도구라기보다, **문서를 반복해서 만들고 고치고 점검하는 작업**에 강한 도구입니다.
- 초안 생성보다 더 인상적이었던 부분은 **`help`, `issues`, `screenshot`처럼 검수까지 이어지는 흐름**이었습니다.
- 다만 PowerPoint 같은 문서는 마지막에 결국 **사람 눈으로 한 번 더 보고 다듬는 과정**이 필요합니다.

## 상황

이번에 저는 `officecli`를 가볍게 훑어본 수준이 아니라, 실제로 소개용 PPT를 한 벌 만들어 보는 데 써 봤습니다.

한 번에 해 본 일은 대략 이 정도였습니다.

1. `officecli`가 이미 설치돼 있는지 확인했습니다.
2. 관련 도움말을 읽으며 어떤 방식으로 보는지, 점검하는지 확인했습니다.
3. 소개용 PowerPoint 파일을 만들고 렌더링했습니다.
4. 슬라이드를 다시 이미지로 뽑아 보고, 넘침이나 배치 문제를 눈으로 확인했습니다.
5. 고친 뒤 다시 뽑아 보면서 어디까지 자동화가 되고, 어디서 사람이 개입해야 하는지 살펴봤습니다.

이 과정을 해 보니, `officecli`는 “문서를 다룬다”기보다 “문서 작업을 절차로 만든다”는 표현이 더 잘 맞았습니다.

## 설치는 어떻게 하나

설치는 아주 단순한 편입니다.

```bash
# macOS / Linux
curl -fsSL https://d.officecli.ai/install.sh | bash

# 설치 확인
officecli --version
```

윈도우 PowerShell에서는 아래처럼 안내합니다.

```powershell
irm https://d.officecli.ai/install.ps1 | iex
```

설치 뒤 새 터미널을 열어야 명령이 바로 잡히는 경우도 있습니다.

## 처음 쓸 때 가장 먼저 보면 좋은 것

이 도구는 기능이 많아서, 기억에 기대고 추측하면서 쓰기 시작하면 오히려 더 헷갈릴 수 있습니다. 그래서 처음에는 아래 세 줄이 제일 중요했습니다.

```bash
officecli help
officecli help pptx
officecli help view
```

특히 좋았던 점은 “속성 이름을 감으로 맞히라”는 분위기가 아니라, `help`를 먼저 보라고 강하게 유도한다는 점입니다. 실제로 이런 류의 도구는 도움말이 약하면 금방 지치는데, `officecli`는 적어도 그 지점은 꽤 잘 챙겨 둔 편이었습니다.

## 실제로는 어떻게 쓰게 되나

제가 보기엔 `officecli`는 세 단계로 이해하면 편합니다.

### 1. 먼저 읽고 확인하기

문서를 바로 고치기보다, 먼저 구조와 문제를 읽어 보는 단계입니다.

```bash
officecli view sample.pptx outline
officecli view sample.pptx issues
officecli view sample.pptx screenshot --page 1 -o slide-1.png
```

이 단계가 중요한 이유는, 파일을 열어 보기 전에도 “슬라이드 구조가 어떤지”, “어디가 넘치는지”, “이미지로 보면 어떤 느낌인지”를 먼저 확인할 수 있기 때문입니다.

### 2. 그다음 고치기

문자열을 바꾸거나, 특정 요소의 속성을 바꾸는 식으로 다룹니다.

```bash
officecli set sample.docx / --find draft --replace final
officecli set sample.xlsx /Sheet1/A1 --prop value="제목"
```

GUI처럼 눈으로 끌어다 놓는 방식은 아니지만, 반복 수정이나 규칙성 있는 수정에는 꽤 편합니다.

### 3. 마지막에 다시 보기

이 부분이 생각보다 좋았습니다. 문서를 수정하고 끝내는 것이 아니라, 다시 이미지나 이슈 목록으로 확인할 수 있습니다.

```bash
officecli view sample.pptx screenshot --page 1-5 --grid 3 -o contact.png
officecli view sample.pptx issues --type format
```

이 흐름 덕분에 “고쳤다”가 아니라 “고친 결과가 실제로 어떻게 보이는지 봤다”까지 이어집니다.

## 써 보니 좋았던 점

### 1. Word, Excel, PowerPoint를 한 계열로 다룰 수 있다

하나의 문서 형식만 다루는 도구가 아니라 `.docx`, `.xlsx`, `.pptx`를 같은 감각으로 접근할 수 있어서 흐름이 통일됩니다. 한 번 익숙해지면 “문서마다 도구가 완전히 다르다”는 느낌이 줄어듭니다.

### 2. 검수 기능이 생각보다 실용적이다

단순히 파일을 생성하는 것보다, `outline`, `issues`, `screenshot` 같은 기능이 꽤 유용했습니다. 특히 PPT는 문장이 박스 안에서 넘치는지, 전체 균형이 어떤지 확인하는 과정이 중요한데, 이걸 CLI 안에서 어느 정도 이어갈 수 있다는 점이 좋았습니다.

### 3. 반복 작업에 강하다

문서 한 개를 한 번 예쁘게 만드는 일보다, 비슷한 문서를 여러 번 만들거나 일정한 규칙으로 바꾸는 작업에서 힘이 납니다. 예를 들어 제목 형식 통일, 특정 문구 치환, 반복 보고서 생성 같은 흐름에 잘 맞습니다.

### 4. “문서를 코드처럼” 다루는 감각이 있다

이건 장점이자 취향의 문제이기도 한데, 문서를 눈으로만 만지는 대신 구조와 명령으로 다룰 수 있다는 점이 분명한 매력입니다. 특히 자동화에 관심이 있는 분에게는 꽤 재미있는 도구입니다.

## 써 보니 아쉬웠던 점

### 1. 처음엔 낯설다

PowerPoint를 직접 열어 슬라이드를 만지는 데 익숙한 분이라면, 경로와 속성 중심으로 다루는 방식이 바로 몸에 들어오지는 않습니다. 처음에는 “지금 내가 뭘 보고 있지?”라는 느낌이 생길 수 있습니다.

### 2. PPT는 여전히 눈으로 봐야 한다

슬라이드는 생성되더라도 실제 화면에서는 글자 넘침, 간격 미세 어긋남, 카드 내부 균형 같은 문제가 남을 수 있습니다. 자동 점검이 있어도 마지막엔 결국 이미지로 다시 보게 됩니다.

### 3. 디자인까지 대신해 주지는 않는다

문서를 만들 수 있는 것과, 보기 좋은 문서를 만드는 것은 조금 다른 문제입니다. `officecli`는 구조와 수정, 점검에는 강하지만, 색감과 레이아웃 감각까지 자동으로 해결해 주는 도구는 아닙니다.

### 4. resident 흐름은 익숙해질 필요가 있다

실제로 쓰다 보면 resident 상태 때문에 한 번 닫고 다시 읽어야 하는 경우가 있습니다. 큰 문제는 아니지만, CLI 특유의 작동 방식을 조금 이해하고 쓰는 편이 편합니다.

## 4060미들스쿨 작업 기준으로 어디에 잘 맞을까

제가 보기엔 이 블로그와 모임 운영 기준에서는 아래 같은 일에 특히 잘 맞습니다.

- 소개 슬라이드 초안 만들기
- 공지용 표나 요약표 정리하기
- Word 문서의 반복 문구나 형식 정리하기
- Excel 파일의 표 제목, 셀 값, 반복 열 구성 손보기
- 문서를 이미지로 다시 뽑아 카카오톡이나 텔레그램에서 확인하기

반대로 아래 같은 일은 아직 사람이 직접 만지는 쪽이 더 편할 수 있습니다.

- 감각적인 발표용 PPT를 마지막까지 정교하게 마감하는 일
- 요소를 마우스로 이리저리 옮기며 보는 편집
- “대충 눈으로 맞춰 가며” 레이아웃을 잡는 작업

## 실제로 시작할 때 추천하는 순서

처음부터 복잡한 문서를 건드리기보다, 아래 순서로 가면 덜 헷갈립니다.

1. 설치하고 `officecli --version`으로 확인합니다.
2. `officecli help`, `officecli help view`를 먼저 봅니다.
3. 이미 있는 간단한 `.docx`나 `.pptx`를 `view outline`으로 읽어 봅니다.
4. `view screenshot`이나 `view issues`로 결과를 확인해 봅니다.
5. 그다음에야 `set`, `add` 같은 수정 명령을 써 봅니다.

이 순서가 좋은 이유는, 처음부터 만들기보다 읽고 확인하는 감각을 먼저 잡게 해 주기 때문입니다.

## 막혔던 지점

> 실제로 써 보니, `officecli`의 핵심 난점은 “설치가 안 된다”보다 “문서는 만들어졌는데 화면 균형을 어디까지 믿어야 하나”에 더 가까웠습니다.

PowerPoint를 만들 때는 구조상으로는 문제없어 보여도, 실제 렌더링에서는 텍스트 높이나 간격이 빠듯한 경우가 있었습니다. 그래서 `issues` 결과와 `screenshot` 결과를 같이 보고, 다시 손보는 방식이 필요했습니다.

이 경험 때문에 저는 `officecli`를 “문서 자동 생성기”보다 “문서 자동화 + 점검 도구”로 보는 쪽이 더 정확하다고 느꼈습니다.

## 남겨둘 판단

`officecli`는 “오피스 문서를 완전히 대신하는 마법 도구”는 아닙니다. 대신 오피스 문서를 반복해서 만들고, 고치고, 확인해야 하는 사람에게는 꽤 실용적인 작업 도구가 될 수 있습니다.

특히 4060미들스쿨처럼 소개 자료, 안내 자료, 표 정리, 실습용 슬라이드가 자주 필요한 흐름에서는 한 번 익혀 둘 가치가 있습니다. 다만 처음부터 너무 큰 기대를 걸기보다, **설치 → 읽기 → 점검 → 간단한 수정** 순서로 천천히 붙이는 편이 더 잘 맞습니다.
