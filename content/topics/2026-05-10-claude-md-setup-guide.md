# 2026년 5월 10일(일) CLAUDE.md 완벽 세팅 가이드

Claude Code를 처음 켜면 많은 분들이 제일 먼저 묻습니다. “매번 같은 말을 다시 해야 하나요?” 이 질문에 가장 현실적인 답이 바로 `CLAUDE.md`입니다. 프로젝트 규칙, 개인 취향, 금지할 일, 작업 흐름을 미리 적어두면 Claude가 매번 처음부터 헤매지 않고 같은 기준으로 따라오게 됩니다.

이번 글은 공유해주신 원문을 바탕으로, 입문자가 먼저 이해하면 좋은 핵심부터 실제 세팅 흐름까지 따라갈 수 있게 정리한 메모입니다. 더 자세한 표와 체크리스트, 연결 노트까지 보려면 원문 링크로 넘어가 읽어보시는 쪽이 더 좋습니다.

## 먼저 결론

- `CLAUDE.md`는 Claude에게 반복해서 말하기 귀찮은 작업 규칙을 미리 적어두는 파일입니다.
- 전역 규칙, 프로젝트 규칙, 개인 로컬 규칙을 나눠두면 훨씬 덜 헷갈립니다.
- 다만 이 파일은 행동을 돕는 지침이지, 보안을 강제로 막는 장치는 아니라는 점은 꼭 구분해야 합니다.

## 가장 먼저 이해하면 좋은 세 가지

처음 시작하는 분은 아래 세 가지만 잡아도 큰 흐름이 잡힙니다.

1. **전역 `CLAUDE.md`**
   - 내 컴퓨터의 모든 프로젝트에 공통으로 적용할 개인 취향을 적는 자리입니다.
   - 예를 들면 한국어로 답하기, 파일 삭제 전 묻기, 테스트 먼저 돌리기 같은 기준이 여기에 들어갑니다.

2. **프로젝트 `CLAUDE.md`**
   - 이 프로젝트에서 팀이 함께 지킬 규칙을 적는 자리입니다.
   - 기술 스택, 폴더 구조, 금지 사항, 자주 쓰는 명령어를 여기에 넣으면 매번 설명할 필요가 줄어듭니다.

3. **`CLAUDE.local.md`**
   - 같은 프로젝트 안에서도 나만 따로 기억하고 싶은 메모를 담는 파일입니다.
   - 개인 메모 성격이 강하므로 `.gitignore`에 넣는 습관이 중요합니다.

## 위치 감각부터 먼저 잡으면 훨씬 덜 헷갈립니다

처음 배우는 분들은 파일 이름보다 **어디에 두는가**에서 더 많이 헷갈립니다. 이 부분을 쉽게 설명해준 점도 원문에서 특히 좋았습니다.

> 컴퓨터 안의 파일 위치는 집 주소와 비슷합니다.
> 집 전체에 적용하는 규칙은 현관 쪽에 두고, 오늘 작업하는 책상에서만 지킬 규칙은 그 책상 위에 둔다고 생각하면 훨씬 이해가 쉽습니다.

### 초보자가 가장 많이 헷갈리는 지점

`CLAUDE.md`는 이름이 같아도 **어느 폴더에 있느냐**에 따라 의미가 달라집니다.

- `~/.claude/CLAUDE.md` = 모든 프로젝트에 적용되는 “내 기본 성격”
- `photo-app/CLAUDE.md` = 사진 앱 프로젝트에서만 적용되는 “이 일터의 규칙”
- `photo-app/CLAUDE.local.md` = 사진 앱 프로젝트에서 나만 보는 “개인 포스트잇”

### 내가 지금 어느 폴더에 있는지 확인하기

프로젝트 파일을 만들기 전에 **현재 위치**를 먼저 확인하는 습관이 중요합니다.

#### macOS / WSL

```bash
pwd
ls
```

- `pwd` = 지금 내가 서 있는 폴더 주소 보기
- `ls` = 이 폴더 안에 뭐가 있는지 보기

#### Windows PowerShell

```powershell
Get-Location
ls
```

- `Get-Location` = 지금 내가 서 있는 폴더 주소 보기
- `ls` = 이 폴더 안에 뭐가 있는지 보기

프로젝트 폴더에 제대로 들어왔을 때는 보통 `package.json`, `src`, `README.md`, `.git` 같은 파일이나 폴더가 보입니다.

### “여기에 만들면 맞나요?” 빠른 판단법

| 상황 | 어디에 만들까요? | 이유 |
|---|---|---|
| 모든 프로젝트에서 한국어로 답하게 하고 싶다 | `~/.claude/CLAUDE.md` | 개인 취향은 전역이 편함 |
| 이 웹사이트 프로젝트의 빌드 명령을 알려주고 싶다 | `웹사이트폴더/CLAUDE.md` | 프로젝트마다 명령이 다름 |
| 내 컴퓨터에서만 쓰는 테스트 서버 주소가 있다 | `프로젝트폴더/CLAUDE.local.md` | 팀원에게 공유할 필요 없음 |
| 회사 전체 보안 규칙을 강제 배포해야 한다 | 조직 관리자 위치 | 일반 초보자는 거의 만질 일 없음 |

- [ ] 파일을 만들기 전에 `pwd` 또는 `Get-Location`으로 현재 위치를 확인했다.
- [ ] 프로젝트 규칙을 바꿀 때는 먼저 프로젝트 폴더로 `cd` 이동했다.
- [ ] 개인 메모는 `CLAUDE.local.md`에 적고 `.gitignore`에 추가했다.
- [ ] 바탕화면, 다운로드 폴더, 문서 폴더에 실수로 `CLAUDE.md`를 만들지 않았다.
- [ ] 숨김 폴더 `.claude`가 안 보여도 당황하지 않는다. 점(`.`)으로 시작해서 숨겨진 것뿐이다.

### 우선순위를 쉽게 이해하면

Claude Code는 작업 폴더에서 위쪽 폴더로 올라가며 `CLAUDE.md`와 `CLAUDE.local.md`를 찾고, 발견한 내용을 함께 읽습니다. 더 가까운 폴더의 지침과 `CLAUDE.local.md`가 나중에 읽히므로 **더 구체적인 내용이 사실상 더 강하게 작동**한다고 이해하면 됩니다.

## 왜 이 파일이 중요한가

입문자 입장에서 가장 무서운 건, AI가 열심히 하다가 내가 원하지 않은 쪽으로 너무 멀리 가버리는 순간입니다. 원문에서도 이 점을 분명하게 짚고 있습니다. Claude Code는 자율적으로 움직이기 때문에 규칙이 없으면 선의로 사양을 넓히거나 불필요한 기능을 붙여버릴 수 있습니다.

그래서 `CLAUDE.md`는 단순한 메모가 아니라, “여기서는 이렇게 일한다”를 먼저 알려주는 작업 설명서에 가깝습니다.

## 꼭 구분해야 할 점

`CLAUDE.md`는 **보안 설정 파일이 아닙니다.**

즉,
- 반드시 막아야 하는 명령
- 파일 접근 제한
- 권한 제어

같은 것은 `settings`, `permissions`, `hooks` 같은 별도 기능으로 다뤄야 합니다. `CLAUDE.md`는 Claude가 더 잘 따르도록 돕는 컨텍스트 지침이라고 보는 편이 정확합니다.

## 프로젝트 CLAUDE.md 만들기

프로젝트 규칙은 팀이 함께 읽는 파일이므로, 개인 취향보다 **기술 스택·명령어·금지 사항·완료 기준**이 들어가는 쪽이 좋습니다.

### 가장 쉬운 방법: `/init`

1. 프로젝트 폴더로 이동합니다.

#### macOS / WSL

```bash
cd ~/내프로젝트폴더
```

#### Windows PowerShell

```powershell
cd "$HOME\내프로젝트폴더"
```

2. Claude Code를 실행합니다.

```bash
claude
```

3. Claude Code 안에서 입력합니다.

```text
/init
```

`/init`은 프로젝트를 훑어보고 `CLAUDE.md` 초안을 만들어 줍니다. 이미 파일이 있으면 덮어쓰기보다 **개선 제안**을 먼저 하는 편입니다.

### 손으로 만들 때 추천 구조

````markdown
# CLAUDE.md - 프로젝트 규칙

## 프로젝트 개요
- 이름: 가족 사진 앨범 정리 앱
- 목적: 폴더에 흩어진 사진을 날짜별로 자동 분류
- 사용자: 60대 부모님도 쉽게 쓰는 앱

## 기술 스택
- 프론트엔드: Vite, HTML, CSS, JavaScript
- 데이터 저장: SQLite 또는 sql.js
- 테스트: Vitest, Playwright

## 폴더 구조
```text
frontend/
├── src/
│ ├── components/ # UI 부품
│ ├── lib/ # 핵심 로직
│ └── pages/ # 화면
└── tests/ # 테스트
```

## 코딩 규칙
- 변수명은 영어 camelCase를 사용합니다.
- 주석은 한국어로 작성합니다.
- 한 파일은 한 가지 책임만 갖도록 유지합니다.

## 자주 쓰는 명령어
- `npm run dev`: 개발 서버 시작
- `npm test`: 테스트 실행
- `npm run build`: 배포용 빌드

## 절대 금지
- `.env` 파일 내용 출력 금지
- `node_modules` 직접 수정 금지

- 수정한 기능을 직접 확인합니다.

````

프로젝트 파일에 개인 포트, 개인 계정, 나만 쓰는 경로를 너무 많이 넣지 않는 것도 중요합니다. 그런 내용은 `CLAUDE.local.md`로 분리하는 편이 더 깔끔합니다.

## CLAUDE.local.md 만들기

같은 프로젝트라도 **나만 쓰는 로컬 정보**가 있을 때는 이 파일이 편합니다.

예를 들면
- 내 개발 서버 포트
- 내 테스트 데이터 경로
- 내 샌드박스 URL

같은 것들입니다.

### 만들기 + Git 제외

#### macOS / WSL

```bash
touch CLAUDE.local.md
echo "CLAUDE.local.md" >> .gitignore
```

#### Windows PowerShell

```powershell
New-Item CLAUDE.local.md -ItemType File -Force
Add-Content -Path .gitignore -Value "CLAUDE.local.md"
```

### 예시 내용

````markdown
# CLAUDE.local.md - 나만의 프로젝트 메모

## 로컬 실행 환경
- 내 개발 서버 포트: 5173
- 테스트용 더미 데이터 위치: `./local-fixtures/`

## 개인 디버깅 메모
- 로그인 테스트는 샌드박스 계정만 사용합니다.
- 실제 고객 데이터는 절대 사용하지 않습니다.
````

여기서도 하나는 꼭 기억해두면 좋겠습니다. `CLAUDE.local.md`도 평문 파일이므로, `.gitignore`에 넣었다고 해도 **API 키나 비밀번호 원문을 적지 않는 것**이 가장 안전합니다.

## 잘 쓴 CLAUDE.md의 기준

좋은 `CLAUDE.md`는 멋있게 쓰는 문서라기보다, **짧고 구체적이고 검증 가능한 문서**에 가깝습니다.

### 7가지 필수 섹션

| 순서 | 섹션 | 질문 |
|---:|---|---|
| 1 | 프로젝트 개요 | 무엇을 만드는가? |
| 2 | 기술 스택 | 어떤 언어·프레임워크·DB를 쓰는가? |
| 3 | 폴더 구조 | 중요한 파일은 어디에 있는가? |
| 4 | 코딩 규칙 | 이름·주석·스타일 규칙은 무엇인가? |
| 5 | 자주 쓰는 명령어 | 개발·테스트·빌드 명령은 무엇인가? |
| 6 | 금지 사항 | 절대 하면 안 되는 행동은 무엇인가? |
| 7 | 완료 기준 | 어떤 검증을 통과해야 끝인가? |

### 길이 가이드

| 파일 | 추천 길이 | 이유 |
|---|---:|---|
| 전역 `~/.claude/CLAUDE.md` | 30~80줄 | 개인 취향만 간결하게 |
| 프로젝트 `CLAUDE.md` | 80~200줄 미만 | 길수록 준수율이 떨어짐 |
| 긴 세부 규칙 | 별도 파일 또는 `.claude/rules/` | 필요한 상황에만 읽히게 분리 |

모호한 문장보다 실행 가능한 문장이 훨씬 낫다는 점도 중요합니다.

- 나쁜 예: “코드를 잘 짜줘”
- 좋은 예: “새 기능을 추가하면 `npm test`를 실행하고 실패 로그를 요약합니다.”

## 조금 더 나중에 보면 좋은 고급 기능

처음에는 전역, 프로젝트, 로컬 3개 파일만 익혀도 충분하지만, 프로젝트가 커지면 아래 기능들이 도움이 됩니다.

### `@파일경로` import

CLAUDE.md 안에서 다른 파일을 불러올 수 있습니다.

````markdown
# CLAUDE.md

@README.md
@docs/git-workflow.md

## Claude Code 전용 지침
- PR 전에는 `npm test`를 실행합니다.
````

### AGENTS.md 연결

Claude Code는 기본적으로 `CLAUDE.md`를 읽습니다. 다른 에이전트용 `AGENTS.md`가 이미 있다면 `CLAUDE.md`에서 `@AGENTS.md`로 연결해 쓸 수 있습니다.

### `.claude/rules/`로 쪼개기

`CLAUDE.md`가 200줄을 넘거나, 프론트엔드·백엔드·테스트 규칙이 섞여 읽기 어려워질 때는 주제별 파일로 나누는 편이 좋습니다.

### Auto memory

사람이 쓰는 `CLAUDE.md`와 별도로, Claude가 스스로 학습 내용을 남기는 auto memory가 있습니다.

- `CLAUDE.md` = 사람이 명시적으로 적는 규칙
- auto memory = 반복 작업에서 Claude가 쌓는 학습

## 자주 하는 실수

실제로는 아래 실수가 가장 많이 나옵니다.

1. 전역과 프로젝트에 똑같은 내용을 중복 작성한다.
2. API 키를 `CLAUDE.md`에 적는다.
3. `CLAUDE.local.md`를 Git에 올린다.
4. 500줄 넘게 장황하게 쓴다.
5. “잘”, “예쁘게”, “알아서” 같은 모호한 표현을 쓴다.
6. `CLAUDE.md`를 보안 강제 장치로 착각한다.
7. 만들어두고 한 번도 점검하지 않는다.

## 오늘 바로 점검할 체크리스트

- [ ] `~/.claude/CLAUDE.md`를 만들었다.
- [ ] 프로젝트 폴더에서 `claude`를 실행했다.
- [ ] `/init`으로 프로젝트 `CLAUDE.md` 초안을 만들었다.
- [ ] 프로젝트 `CLAUDE.md`에 빌드·테스트 명령을 적었다.
- [ ] 개인 메모가 필요하면 `CLAUDE.local.md`를 만들었다.
- [ ] `CLAUDE.local.md`를 `.gitignore`에 추가했다.
- [ ] `/memory`를 열어 현재 로드된 파일을 확인했다.

Claude에게 이렇게 물어보는 방식도 꽤 좋습니다.

```text
지금 읽은 CLAUDE.md 규칙을 전역/프로젝트/로컬로 나눠서 3줄로 요약해줘.
```

Claude가 내가 적은 규칙을 제대로 요약하고, 프로젝트 명령어와 금지사항을 정확히 말하면 세팅이 꽤 잘 된 것입니다.
