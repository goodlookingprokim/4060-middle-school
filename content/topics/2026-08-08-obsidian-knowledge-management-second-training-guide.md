# 옵시디언이 메모장으로 끝나지 않게, 지식 창고로 바꾸는 가장 쉬운 시작법

출처와 감사

- 이 글은 `옵시디언 지식 관리 구성 2차 연수 자료`를 바탕으로, 4060미들스쿨 블로그 독자 기준에 맞게 다시 풀어 쓴 정리입니다.
- 원문은 설치, Vault, 폴더, 링크, 태그, 검색, QMD, MCP까지 한 흐름으로 정리된 연수용 자료였습니다.
- 블로그에서는 같은 내용을 조금 더 가볍게 읽히도록 줄기를 추리고, 처음 시작하는 분이 바로 따라 할 수 있는 순서로 다시 묶었습니다.

옵시디언을 처음 열면 보통 두 갈래로 나뉩니다.  
한쪽은 "와, 정리 잘하면 정말 좋겠다" 하고 기대하고, 다른 한쪽은 "이거 잘못 건드리면 더 복잡해지는 것 아닐까" 하고 겁이 납니다.

사실 그 두 마음이 같이 드는 게 자연스럽습니다. 옵시디언은 기능이 많은 도구라서, 처음부터 잘하려고 들면 금방 메모보다 구조에 더 많은 시간을 쓰게 되기 때문입니다.

이번 글은 그 지점에서 출발합니다.  
대상은 **옵시디언을 쓰고 싶지만 아직 두려운 사람**입니다. 멋진 그래프 화면이나 복잡한 플러그인보다, 먼저 "내가 적은 메모를 나중에 다시 찾고 다시 쓸 수 있게 만드는 흐름"부터 잡아보려 합니다.

## 먼저 결론

- 옵시디언은 정리를 잘하는 사람만 쓰는 도구가 아닙니다. 오히려 **기록은 많은데 다시 못 찾는 사람**에게 더 잘 맞습니다.
- 처음 한 달은 폴더를 많이 만들 필요가 없습니다. `00_Inbox`, `10_Work`, `20_Life`, `30_Learning`, `90_Templates` 다섯 칸이면 충분합니다.
- 첫 시작은 예쁜 노트가 아니라 `홈`, `오늘 할 일`, `업무 아이디어 모음` 세 장이면 됩니다.
- 기록은 길게 쓰는 것보다 **나중의 내가 알아볼 수 있게 쓰는 것**이 중요합니다.
- QMD는 처음부터 꼭 필요한 건 아니지만, 노트가 쌓인 뒤에는 "내 노트 창고에서 다시 찾아오는 검색 도우미"로 꽤 유용합니다.

## 왜 자꾸 적어 놓고도 못 찾게 될까

문제는 기록을 안 해서가 아닙니다. 대개는 여기저기에 흩어져 있어서 그렇습니다.

- 회의 메모는 메신저에 있고
- 오늘 할 일은 휴대폰 메모장에 있고
- 읽어 둔 좋은 글은 브라우저 북마크에 있고
- 보고서 초안은 바탕화면 어딘가에 있고
- 언젠가 쓰려고 적어 둔 한 줄은 어디 있는지 기억이 안 납니다

그래서 나중에 "분명 지난달에 비슷한 걸 적어 놨는데" 하고 찾기 시작하면, 기록이 없는 게 아니라 **흐름이 없는 것**이 문제였다는 걸 알게 됩니다.

옵시디언이 여기서 해 주는 일은 거창하지 않습니다.

> 기록이 들어오고, 정리되고, 연결되고, 다시 나오는 흐름을 한곳에 모아 주는 것

이 감각만 잡혀도 옵시디언은 훨씬 덜 무섭습니다.

## 옵시디언을 아주 쉽게 보면 이렇다

옵시디언은 그냥 노트 앱이라고만 생각해도 틀리지는 않습니다. 하지만 초보에게는 이렇게 이해하는 편이 더 쉽습니다.

> 옵시디언은 내 컴퓨터 안에 만드는 개인 지식 창고다.

창고라고 생각하면 이해가 빨라집니다.

- Vault는 큰 창고입니다.
- 폴더는 창고 안 구역입니다.
- 노트는 상자 안에 넣는 물건입니다.
- 제목과 태그는 이름표입니다.
- 링크는 상자와 상자 사이의 길입니다.
- 홈 노트는 자주 가는 곳을 모아 둔 안내판입니다.

여기서 중요한 질문은 하나입니다.

> 이 기록을 나중에 어디에서 다시 쓸까

이 질문이 생기면, 옵시디언은 장식용 메모장이 아니라 다시 꺼내 쓰는 공간이 됩니다.

## 처음 한 달은 이 다섯 폴더면 충분하다

초보가 가장 먼저 빠지기 쉬운 함정은 폴더를 너무 많이 만드는 것입니다.  
업무, 회의, 자료, 아이디어, 프로젝트, 독서, 일정, 여행, 건강 식으로 늘리기 시작하면, 메모를 하기 전에 어디에 넣을지부터 고민하게 됩니다.

처음에는 아래 다섯 개만 추천합니다.

```text
00_Inbox
10_Work
20_Life
30_Learning
90_Templates
```

각 폴더는 이렇게 생각하면 됩니다.

- `00_Inbox`: 아직 정리 안 된 메모를 일단 넣는 곳
- `10_Work`: 회의, 보고서, 업무 요청, 개선 아이디어
- `20_Life`: 장보기, 병원 예약, 집안일, 여행 준비
- `30_Learning`: 책, 강의, 새로운 도구 사용법, 배운 것 메모
- `90_Templates`: 반복해서 쓰는 양식 보관

핵심은 폴더 수가 아니라 **넣는 부담을 줄이는 것**입니다.  
어디에 넣어야 할지 애매하면 `00_Inbox`에 먼저 넣고, 나중에 정리하면 됩니다.

## 처음에는 노트도 세 장이면 시작된다

복잡한 대시보드 대신 아래 세 장부터 만들어도 충분합니다.

### 1. `홈`

옵시디언을 열었을 때 길을 잃지 않게 해 주는 안내판입니다.

```markdown
# 홈

## 빠른 이동
- [[오늘 할 일]]
- [[업무 아이디어 모음]]
- [[생활 체크리스트]]
- [[배운 것 모음]]
```

### 2. `오늘 할 일`

하루의 책상 같은 노트입니다.

```markdown
# 오늘 할 일

- [ ] 오늘 꼭 끝낼 일 1개
- [ ] 연락할 사람 1명
- [ ] 정리할 메모 1개

## 떠오른 생각
-
```

### 3. `업무 아이디어 모음`

떠오른 불편함과 개선 생각을 쌓아 두는 노트입니다.

```markdown
# 업무 아이디어 모음

## 불편한 점
-

## 개선 아이디어
-

## 다음 행동
- [ ]
```

처음엔 이 세 장만 있어도 됩니다.  
중요한 건 노트를 많이 만드는 게 아니라, **다시 돌아올 자리를 만드는 것**입니다.

## 좋은 노트는 길지 않아도 된다

많은 분이 "정리를 잘하려면 길고 자세하게 써야 하나" 하고 부담을 느낍니다. 꼭 그렇지는 않습니다.

이런 메모는 나중에 다시 보기 어렵습니다.

```markdown
# 메모

고객 안내 문구 너무 김. 나중에 개선.
```

왜 아쉽냐면, 나중의 내가 봐도 무슨 문구였는지, 왜 길다고 느꼈는지, 무엇을 바꾸려 했는지 알기 어렵기 때문입니다.

조금만 더 써 주면 훨씬 좋아집니다.

```markdown
# 고객 응대 안내 문구 개선

## 발견한 문제
신청 절차 안내 문장이 길어서 처음 읽는 사람이 다음 행동을 바로 알기 어렵다.

## 다음 행동
- [ ] 첫 문장을 한 줄로 줄이기
- [ ] 자주 묻는 질문 3개를 위로 올리기
```

노트는 멋져야 하는 게 아니라, **나중의 내가 읽어도 이해되어야** 합니다.

## 링크와 태그는 많이보다 적당히

옵시디언의 재미는 링크와 태그에 있지만, 초보일수록 많이 붙이기보다 기준을 적게 잡는 편이 좋습니다.

링크는 이렇게 생각하면 됩니다.

- 나중에 다시 볼 가능성이 있는가
- 관련된 다른 노트가 있는가
- 앞으로 계속 자랄 주제인가

그럴 때만 `[[업무 아이디어 모음]]`처럼 연결하면 됩니다.

태그도 처음엔 다섯 개면 충분합니다.

```text
#확인필요
#진행중
#완료
#아이디어
#나중에
```

폴더는 "어디에 두는가"를 알려 주고, 태그는 "지금 어떤 상태인가"를 알려 준다고 생각하면 편합니다.

## 검색이 잘 되려면 제목부터 달라야 한다

옵시디언을 잘 쓰는 사람은 모든 것을 기억하려고 하지 않습니다. 대신 **찾을 수 있게 적어 둡니다.**

예를 들어 `메모`, `정리`, `나중에` 같은 제목은 검색할 때 도움이 거의 되지 않습니다.  
반대로 `고객 응대 안내 문구 개선`, `병원 예약 확인`, `7월 독서 메모` 같은 제목은 나중에 내가 떠올릴 단어가 들어 있습니다.

검색은 마법이 아니라, 미래의 나를 위해 단서를 심어 두는 일에 가깝습니다.

그래서 흐름은 단순합니다.

1. 찾을 만한 단어로 제목을 적는다.
2. 본문에 핵심 상황을 한두 줄 남긴다.
3. 다음 행동을 적는다.
4. 필요하면 관련 노트와 링크한다.

이 정도만 해도 "적어 놓고 잊는 메모"가 많이 줄어듭니다.

## 매일 5분, 주 1회 15분이면 충분하다

옵시디언은 오래 붙잡는 것보다 짧게 자주 쓰는 편이 더 좋습니다.

### 매일 5분

- 오늘 할 일 3개 적기
- 들어온 정보 1개 적기
- 급한 메모는 `00_Inbox`에 넣기

### 주 1회 15분

- `00_Inbox` 비우기
- 제목이 애매한 노트 바꾸기
- 관련 노트 2개 연결하기
- 끝난 일에는 `#완료` 붙이기

### 월 1회 30분

- 자주 보는 노트를 `홈`에 추가하기
- 반복되는 양식은 템플릿으로 만들기
- 너무 커진 노트는 나누기

복잡한 시스템보다 **계속 쓰는 시스템**이 훨씬 낫습니다.

## QMD는 언제 붙이면 좋을까

여기까지는 옵시디언만으로도 충분히 시작할 수 있습니다.  
그다음 단계에서 도움이 되는 것이 QMD입니다.

쉽게 말하면 QMD는 이렇습니다.

> 내 컴퓨터 안의 마크다운 노트를 읽어 두었다가, 키워드나 자연어 질문으로 다시 찾게 도와주는 로컬 검색 도우미

초급자가 처음부터 꼭 설치할 필요는 없습니다. 아래에 가까울 때 배우면 좋습니다.

- 노트가 점점 많아지고 있다
- 제목은 기억나지 않지만 내용으로 찾고 싶다
- 예전 메모를 바탕으로 글이나 보고서 초안을 만들고 싶다
- AI가 내 노트를 참고해서 더 정확히 도와주면 좋겠다

반대로 노트가 아직 몇 장 안 된다면, QMD보다 먼저 폴더, 링크, 제목, 기본 검색에 익숙해지는 편이 좋습니다.

## QMD는 이렇게 이해하면 덜 어렵다

QMD에서 초보가 기억할 건 네 가지뿐입니다.

```text
QMD 설치 = 검색 도구를 준비하는 일
컬렉션 = 어떤 노트 폴더를 검색할지 정하는 일
update = 노트를 다시 읽어 최신 상태로 만드는 일
query = 자연어로 관련 노트를 찾아보는 일
```

대표 명령어도 이 정도만 보면 됩니다.

```bash
npm install -g @tobilu/qmd
qmd --version
qmd collection add ~/Documents/MyNotes --name my-notes
qmd update --collection my-notes
qmd embed --collection my-notes
qmd search "고객 안내 문구" --collection my-notes
qmd query "신청 절차를 더 쉽게 안내하는 방법" --collection my-notes
```

물론 초보에게는 이 명령어 자체가 벌써 부담일 수 있습니다. 그래서 원문 연수 자료에서 특히 좋았던 점이 하나 있습니다.

직접 입력이 어려운 사람을 위해, **AI에게 부탁하는 프롬프트 방식**을 함께 제시했다는 점입니다.

예를 들어 이런 식입니다.

```text
내 컴퓨터에서 Obsidian 노트를 검색하기 위해 QMD를 설치하고 싶습니다.
저는 터미널 명령어에 익숙하지 않습니다.

다음 순서로 안전하게 점검해 주세요.
1. Node.js와 npm이 설치되어 있는지 확인해 주세요.
2. QMD를 설치할 수 있는 환경인지 확인해 주세요.
3. 제 Obsidian Vault 폴더 위치를 물어봐 주세요.
4. 비밀번호, 개인정보, 회사 비공개 자료가 들어 있는 폴더는 검색 대상으로 등록하지 말라고 안내해 주세요.
5. 아직 설치하지 말고, 점검 결과와 다음 단계만 쉽게 설명해 주세요.
```

좋은 점은, 무턱대고 설치부터 하지 않고 **점검부터 하게 만든다**는 것입니다.

## QMD를 붙여도 원문 확인은 꼭 해야 한다

QMD가 찾아 준 결과는 답이 아니라 후보입니다.  
이 원칙은 꼭 기억해 둘 만합니다.

```text
찾기 → 읽기 → 확인하기 → 다시 쓰기
```

예전 노트에서 비슷한 문장이 나왔다고 해서 그대로 복사해 쓰면, 지금 상황과 어긋날 수 있습니다.  
QMD는 "관련 있어 보이는 것을 빨리 찾아주는 사서"에 가깝고, 판단은 여전히 사람이 해야 합니다.

그래서 보고서나 블로그 초안을 쓸 때도 흐름은 같습니다.

1. QMD로 관련 노트를 찾는다.
2. 원문 노트를 직접 읽는다.
3. 지금 목적과 맞는지 확인한다.
4. 필요한 내용만 새 문맥에 맞게 다시 쓴다.

이 습관이 있으면 AI 도움을 받아도 글이 덜 흔들립니다.

## 민감 정보는 애초에 안 넣는 쪽이 낫다

지식 관리를 잘하려면 많이 적는 것보다, **무엇을 적지 말아야 하는지** 아는 것이 더 중요할 때가 많습니다.

옵시디언에 그대로 넣지 않는 편이 좋은 것은 이런 것들입니다.

- 주민등록번호, 여권번호, 면허번호
- 계정 비밀번호, 인증번호, 복구 코드
- 은행 계좌 전체 번호, 카드 번호
- 다른 사람의 연락처와 민감한 사정
- 회사나 기관의 비공개 자료 원문
- 건강, 상담, 평가, 민원 같은 민감한 기록 원문

꼭 기록이 필요하다면 원문 대신 맥락만 남기는 편이 좋습니다.

- `김OO 고객의 전화번호와 민원 원문 전체`
  대신
- `신청 절차가 어렵다는 문의가 반복됨`

이렇게 바꾸면 흐름은 남기고 위험은 줄일 수 있습니다.

## 처음 한 달 추천 구성

끝으로, 정말 처음 시작하는 분이라면 아래 구성만 잡고 한 달 써보면 좋겠습니다.

### 폴더

```text
00_Inbox
10_Work
20_Life
30_Learning
90_Templates
```

### 노트

```text
홈
오늘 할 일
업무 아이디어 모음
생활 체크리스트
배운 것 모음
나중에 볼 자료
```

### 태그

```text
#확인필요
#진행중
#완료
#아이디어
#나중에
```

### 루틴

```text
매일 5분: 기록 넣기
주 1회 15분: Inbox 정리
월 1회 30분: 홈과 템플릿 정리
```

이 정도만 돌아가도 옵시디언은 "어려운 메모 프로그램"이 아니라 "다시 찾을 수 있는 기록 창고"로 바뀌기 시작합니다.

## 마무리

옵시디언을 처음 배울 때 가장 중요한 건 완벽한 시스템이 아닙니다.  
기록이 들어오고, 연결되고, 다시 나오는 흐름을 만드는 일입니다.

처음부터 예쁘게 꾸밀 필요도 없고, 플러그인을 잔뜩 설치할 필요도 없습니다.  
오늘은 폴더 다섯 개, 노트 세 장, 그리고 "나중에 다시 찾을 수 있게 적는다"는 원칙 하나면 충분합니다.

QMD와 MCP 같은 도구는 그다음 단계에서 붙여도 늦지 않습니다. 먼저는 내 기록을 내가 덜 잃어버리는 경험을 하는 것이 더 중요합니다.

좋은 기록은 대단한 문장이 아니라, 나중의 나를 도와주는 동료에 가깝습니다.  
옵시디언도 결국 그 동료를 하나씩 만들어 가는 과정이라고 보면 훨씬 편합니다.
