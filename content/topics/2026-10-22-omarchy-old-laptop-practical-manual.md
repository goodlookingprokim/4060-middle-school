## 1부. 시작하기 전에

### 01. 이 매뉴얼의 사용법과 확인 범위

#### 01-1. 누구를 위한 문서인가요?

다음과 같은 분을 위한 문서입니다.

- 오래된 Windows 노트북을 다시 활용하려는 사람
- 맥북으로 Linux 설치 USB를 만들려는 사람
- 운영체제를 처음 설치하는 사람
- Omarchy의 창 배치와 단축키가 낯선 사람
- 한글 입력을 설정하려는 사람
- Linux를 유지하면서 Windows 프로그램도 사용하려는 사람
- 실습 경험을 교안·블로그·인포그래픽으로 정리하려는 사람

설치 경험이 없더라도 따라갈 수 있도록 개념과 절차를 함께 설명합니다.

다만 운영체제 설치에는 데이터 삭제 위험이 있습니다.

**설치 디스크를 선택하는 순간에는 속도보다 확인이 우선입니다.**

#### 01-2. 이 문서는 무엇을 통합했나요?

1. 맥에서 설치 USB를 준비한 대화
2. HP 250 G7에 Omarchy를 설치한 과정
3. 설치 도구·부팅·한글 입력 문제 해결
4. 창 조작·알림·단축키 사용 경험
5. Windows VM 설치·실행 안내
6. 추가로 제공된 Windows VM 안정화 기록
7. LocalSend 등 공식 문서 기반 활용 안내
8. Apple 앱 개발 환경에 대한 선택 도전 자료
9. 용어 설명·실습 미션·점검표

단순히 대화를 시간순으로 붙인 문서는 아닙니다.

중복은 줄이고, 잘못 전달될 수 있던 내용은 바로잡았습니다.

#### 01-3. 확인 수준을 구분합니다

##### [실습 확인]

사용자 화면 또는 실습 결과 보고로 확인한 내용입니다.

예:

- 설치 USB 제작 완료
- Omarchy 바탕화면 진입
- USB 없이 정상 부팅
- Omarchy에서 한글 입력 성공

##### [추가 기록]

첨부된 「Windows VM 설치 오류와 안정화 기록」에 보고된 내용입니다.

해당 자료는 2026년 10월 22일 작성됐고, 실제 작업·검증 시점은 2026년 10월 14~15일입니다.

이번 편집에서는 정리 문서를 확인했습니다.

문서가 참조한 원본 JSON·스크립트·실행기 코드를 모두 직접 열어 재검증한 것은 아닙니다.

##### [공식 문서]

공식 매뉴얼이나 해당 기술의 공식 자료에 설명된 기능입니다.

이번 HP에서 그 기능까지 직접 시험했다는 뜻은 아닙니다.

##### [권장]

안전하고 쉬운 실습을 위한 제안입니다.

공식 최소 사양이나 필수 조건과 구분합니다.

##### [확인 필요]

다음과 같은 내용입니다.

- 정확한 원인을 밝히지 못한 오류
- 실제 성공 결과가 없는 설정
- 특정 기기에서의 성능
- 현재 상태를 다시 검사해야 하는 항목

#### 01-4. 설치 버전과 현재 공식 문서는 다를 수 있습니다

이번에 설치한 버전은 **Omarchy 4.0.4**입니다.

공식 웹 매뉴얼은 계속 업데이트됩니다.

다음은 달라질 수 있습니다.

- 메뉴 이름과 위치
- 단축키
- 기본 제공 앱
- 설치 질문 순서
- 명령어의 하위 명령
- 보안 정책

예를 들어 테마 메뉴는 실습 당시 `Style`, 현재 확인한 문서에는 `Appearance`로 표시됩니다.

자신의 기기에서는 다음 순서로 확인합니다.

1. `Super + K`로 단축키 안내 확인
2. 메뉴에서 기능 이름 검색
3. 실제 화면 확인
4. 현재 공식 문서 확인

**다른 글과 다르다고 설정을 무작정 덮어쓰지 않습니다.**

#### 01-5. 키 표기

- `Super`: 일반 PC 키보드의 Windows 로고 키
- `Return`: Enter
- `Space`: 스페이스바
- `Arrow`: 방향키
- `Ctrl`: Control
- `Alt`: Alt
- `Shift`: Shift

예:

```text
Super + Enter
```

Windows 키를 누른 상태에서 Enter를 누릅니다.

```text
Super + Shift + →
```

Windows 키와 Shift를 누른 상태에서 오른쪽 방향키를 누릅니다.

#### 01-6. 명령어 사용 원칙

1. 어느 컴퓨터에서 실행하는지 확인합니다.
2. 한 줄씩 실행하고 결과를 확인합니다.
3. 오류가 나오면 다음 단계로 넘어가지 않습니다.
4. 비밀번호는 직접 입력하고 공개하지 않습니다.
5. 설명용 자리표시는 실제 값으로 바꿉니다.
6. 다른 업데이트나 설치가 진행 중인지 확인합니다.

이 문서에서는 실행 환경을 다음처럼 구분합니다.

- 맥 터미널
- Omarchy 터미널
- Windows 화면 또는 PowerShell
- BIOS·부팅 메뉴

### 02. Omarchy는 무엇인가요?

#### 02-1. 한 문장으로 이해하기

**Omarchy는 Arch Linux를 기반으로, 개발과 일상 작업에 필요한 도구·디자인·작업 방식을 미리 조합한 Linux 환경입니다.**

Windows의 테마만 바꾸는 프로그램이 아닙니다.

이번 실습에서는 HP 노트북의 운영체제로 직접 설치했습니다.

#### 02-2. 구성 요소를 쉽게 이해하기

##### Arch Linux

운영체제의 기반입니다.

패키지 설치·업데이트 등 기본 시스템을 담당합니다.

##### Hyprland

창을 어떻게 배치하고 이동할지 관리하는 핵심 구성 요소입니다.

자동 창 배치와 키보드 중심 조작이 Omarchy의 특징으로 느껴지는 이유입니다.

##### Quickshell 기반 화면 구성

상단바·메뉴·알림 등 데스크톱 경험을 구성합니다.

##### 미리 선택된 도구와 설정

터미널·편집기·브라우저·문서 앱과 여러 설정이 조합돼 있습니다.

모든 것을 처음부터 고르기보다, 준비된 환경으로 시작하는 방식입니다.

#### 02-3. Windows와 가장 다르게 느껴지는 점

##### 창이 자동으로 나뉩니다

새 창을 열면 기존 창 옆이나 아래로 배치될 수 있습니다.

이를 타일링 방식이라고 합니다.

##### 키보드 중심입니다

메뉴·창 이동·작업 공간·캡처 등을 단축키로 빠르게 실행합니다.

##### 터미널을 자주 사용합니다

일부 설정과 설치는 명령어로 처리합니다.

##### 사용자가 설정을 직접 다룰 수 있습니다

편리하지만 잘못 바꾸면 불편해질 수도 있습니다.

그래서 백업과 변경 기록이 중요합니다.

#### 02-4. 어떤 사람에게 어울리나요?

- 오래된 컴퓨터를 학습용으로 활용하고 싶은 사람
- Linux를 배우고 싶은 사람
- 키보드 중심 작업을 익히고 싶은 사람
- 개발 도구를 사용하려는 사람
- 시스템을 조금씩 이해하고 바꿔보고 싶은 사람

#### 02-5. 처음부터 기대하면 안 되는 것

- 모든 Windows 프로그램의 직접 실행
- 모든 하드웨어의 완벽한 호환
- 모든 게임의 실행
- Windows와 동일한 조작 방식
- 설치 후 아무 관리도 필요 없는 환경

Windows 전용 앱은 대체 앱·웹 서비스·가상머신 등을 검토해야 합니다.

#### 02-6. 설치 방식 세 가지

##### 컴퓨터에 직접 설치

실제 하드웨어에서 Omarchy를 실행합니다.

이번 HP 실습의 방식입니다.

##### 다른 운영체제 안의 가상머신

기존 Windows나 macOS를 유지하면서 창 안에서 Omarchy를 시험합니다.

처음 대화에서는 이 방식으로 잘못 이해했지만, 사용자의 실제 목표는 직접 설치였습니다.

##### USB에서만 사용하는 환경

내부 디스크에 설치하지 않고 USB 중심으로 사용하는 별도 구성입니다.

이번에 만든 USB는 그 목적이 아니라 **내부 디스크에 설치하기 위한 설치 USB**였습니다.

### 03. 이번 실습의 장비와 전체 구성

#### 03-1. 준비용 컴퓨터

[실습 확인]

- MacBook Pro
- Apple M1 Pro
- 메모리 32GB

맥북에는 Omarchy를 설치하지 않았습니다.

역할:

- 공식 자료 조사
- ISO 다운로드
- 설치 USB 제작

macOS 제품명은 다시 확인하지 않은 표현을 반복하지 않고 생략합니다.

#### 03-2. 설치 대상

[실습 확인]

- HP 250 G7
- 내부 NVMe 디스크
- 장치 경로: `/dev/nvme0n1`
- 표시 용량: 약 238.5GB

[확인 필요]

- CPU 세부 모델
- RAM 용량
- 무선랜 칩셋
- 배터리 상태
- 장시간 발열·절전 복귀 안정성

같은 모델명이라도 부품 구성이 다를 수 있습니다.

#### 03-3. 설치 USB

[실습 확인]

- 약 32GB
- 디스크 유틸리티: 약 31.44GB
- Imager: 약 31.5GB
- 초기 볼륨 이름: `NO NAME`
- 초기 파일시스템: FAT32

표시 방식에 따라 용량이 조금 달라도 이상하지 않습니다.

#### 03-4. 사용한 프로그램

- balenaEtcher 2.1.7: ISO 열기 오류
- Raspberry Pi Imager 2.0.12: 대체 도구로 제작 완료
- Omarchy ISO: `omarchy-4.0.4.iso`

4.0.4는 실제 사용 버전이지, 앞으로도 항상 최신이라는 뜻이 아닙니다.

#### 03-5. 최종 구성

```text
맥북
└─ Omarchy 설치 USB 제작

HP 250 G7
└─ Omarchy
   ├─ 브라우저·터미널·문서·한글 입력
   └─ Windows 가상머신
```

Windows VM은 처음 지운 기존 Windows와 별개의 새 환경입니다.

### 04. 초보자를 위한 용어 사전

#### 운영체제·설치

##### 운영체제, OS

컴퓨터의 기본 동작과 프로그램 실행을 관리하는 소프트웨어입니다.

Windows·macOS·Linux가 대표적입니다.

##### Linux 배포판

Linux를 기반으로 도구와 설치 방식 등을 묶어 제공하는 형태입니다.

##### ISO

운영체제 설치에 필요한 내용을 담은 이미지 파일입니다.

USB에 단순 복사하는 것과 기록 도구로 쓰는 것은 다릅니다.

##### 부팅

컴퓨터 전원을 켜 운영체제를 시작하는 과정입니다.

##### 부팅 USB

컴퓨터를 USB에서 시작할 수 있도록 만든 장치입니다.

이번 USB는 설치 프로그램을 실행하는 용도입니다.

##### BIOS·UEFI

운영체제보다 먼저 실행돼 하드웨어와 부팅 장치를 준비하는 펌웨어 환경입니다.

##### Secure Boot

허용된 서명 등을 확인해 부팅을 제한하는 보안 기능입니다.

설치 운영체제의 지원 방식에 따라 설정 조정이 필요할 수 있습니다.

##### TPM

암호화 키 보호 등에 사용되는 보안 구성 요소입니다.

기능 해제와 내부 키 초기화는 같은 작업이 아닙니다.

##### BitLocker

Windows의 저장장치 암호화 기능입니다.

부팅 보안 설정 변경 후 복구 키를 요구할 수 있습니다.

##### 파티션

저장장치를 논리적으로 나눈 구역입니다.

##### 전체 디스크 설치

선택한 디스크 전체를 새 운영체제 용도로 사용하는 설치입니다.

기존 파일이 삭제될 수 있습니다.

##### 듀얼 부팅

한 컴퓨터에 여러 운영체제를 설치하고 시작할 때 선택하는 방식입니다.

이번 실습에서는 진행하지 않았습니다.

##### 부트로더

운영체제를 시작하도록 연결하는 소프트웨어입니다.

이번 기록에는 GRUB 화면과 Omarchy 부팅 메뉴가 등장합니다.

##### Limine

Omarchy 공식 문서에서 기본 부트로더와 스냅샷 부팅에 사용하는 것으로 설명하는 도구입니다.

#### 저장장치·파일

##### NVMe·SSD

빠른 저장장치와 관련된 기술·제품 구분입니다.

이번 내부 디스크는 NVMe로 표시됐습니다.

##### 장치 경로

Linux에서 디스크 등을 나타내는 이름입니다.

예:

```text
/dev/nvme0n1
```

기기마다 다를 수 있습니다.

##### 파일시스템

저장장치에 파일을 저장하고 관리하는 방식입니다.

예:

- FAT32
- NTFS
- Linux용 파일시스템

##### 홈 폴더

현재 사용자의 개인 파일 공간입니다.

Linux에서는 보통 `~`로 줄여 씁니다.

##### 권한

누가 파일을 읽고 쓰고 실행할 수 있는지 정하는 설정입니다.

##### setgid

파일·디렉터리에 붙는 추가 권한 속성입니다.

디렉터리에서는 그룹 상속 등에 관여합니다.

이번 VM 사례에서는 실행기가 요구한 정확한 권한과 충돌했습니다.

##### SHA-256

파일의 내용을 계산해 긴 확인값을 만드는 방식입니다.

공식 값과 비교해 다운로드한 파일이 같은지 확인하는 데 사용합니다.

#### 화면·입력

##### 타일링

창을 겹쳐놓기보다 화면을 나눠 자동 배치하는 방식입니다.

##### 포커스·초점

현재 키 입력을 받는 창이나 입력칸입니다.

##### 작업 공간

여러 개의 가상 책상처럼 창을 나눠 쓰는 공간입니다.

##### 키보드 배열

물리 키와 문자·기호의 연결 방식입니다.

키 입력을 조합해 한글 등 문자를 만드는 도구입니다.

Linux에서 사용하는 입력기 프레임워크입니다.

이번 Omarchy 한글 입력 설정에 사용했습니다.

##### Microsoft IME

Windows의 한국어 입력기입니다.

Omarchy의 Fcitx5와 별개입니다.

##### 클립보드

복사한 텍스트·이미지 등을 잠시 보관하는 기능입니다.

##### OCR

이미지 속 글자를 텍스트로 추출하는 기술입니다.

추출 결과는 원문과 대조해야 합니다.

#### 가상머신·관리

##### 호스트

가상머신을 실행하는 바깥 운영체제입니다.

이번에는 Omarchy입니다.

##### 게스트

가상머신 안에서 실행되는 운영체제입니다.

이번에는 Windows입니다.

##### VM

Virtual Machine, 가상 컴퓨터입니다.

##### KVM

Linux에서 하드웨어 가상화를 활용하는 기반 기술입니다.

##### Docker

컨테이너를 관리하는 도구입니다.

이번 Windows 구성에서는 가상머신을 관리하는 실행 환경에 관여합니다.

Windows가 일반 Linux 앱으로 직접 실행되는 것은 아닙니다.

##### RDP

원격 컴퓨터의 화면을 보고 조작하는 연결 방식입니다.

VM 실행과 화면 연결은 구분해야 합니다.

##### localhost·127.0.0.1

현재 사용 중인 컴퓨터 자신을 뜻합니다.

HP에서의 localhost와 맥북에서의 localhost는 서로 다릅니다.

##### 드라이버

운영체제가 장치를 사용할 수 있게 연결하는 소프트웨어입니다.

가상머신에도 가상 장치용 드라이버가 필요할 수 있습니다.

##### 스냅샷

특정 시점의 시스템 상태를 보관하는 기능입니다.

어떤 파일이 포함되는지는 별도로 확인해야 합니다.

##### 백업

원본 문제에 대비해 다른 위치에 자료를 복사·보관하는 것입니다.

공유 폴더나 시스템 스냅샷과 같은 뜻이 아닙니다.

##### 빌드

소스 코드를 실행 가능한 프로그램으로 만드는 과정입니다.

##### SDK

특정 플랫폼용 프로그램을 만들 때 필요한 개발 자료·도구 묶음입니다.

##### 앱 서명

앱의 제작·배포 주체와 실행 권한 등을 확인하기 위한 절차입니다.

### 05. 설치 전 안전 준비

#### 05-1. 가장 먼저 백업합니다

전체 디스크 설치로 삭제될 수 있는 것:

- Windows
- 바탕화면 파일
- 문서·사진·다운로드
- 설치된 프로그램
- 제조사 복구 파티션
- 로컬에만 있는 브라우저 자료

확인:

- [ ] 중요한 파일을 다른 저장장치에 복사했다.
- [ ] 다른 기기에서 백업 파일이 열리는지 확인했다.
- [ ] 유료 프로그램 재설치 방법을 확인했다.
- [ ] 계정 복구 수단을 확보했다.
- [ ] 필요하면 Windows 복구 USB를 준비했다.

이번 대화에서는 백업을 반복 안내했지만 백업 파일 자체를 검사하지는 않았습니다.

따라서 “백업까지 검증한 설치”로 과장하지 않습니다.

#### 05-2. 암호화·복구 키

기존 Windows가 BitLocker·장치 암호화를 사용하면 BIOS 변경 후 복구 키를 요구할 수 있습니다.

순서:

1. 파일 백업
2. 복구 키 확보
3. 공개 기록에서 키 제외
4. BIOS 변경

**TPM Clear·Reset을 무심코 선택하지 않습니다.**

#### 05-3. 준비물

- HP 노트북
- 전원 어댑터
- 맥북
- 설치 USB
- 필요 시 USB-C 어댑터
- 인터넷
- 백업 저장장치

[권장]

이번 이미지 크기를 고려하면 16GB 이상 USB를 준비하는 편이 좋습니다.

모든 버전의 공식 최소 용량을 뜻하지는 않습니다.

#### 05-4. 불필요한 저장장치 분리

잘못 지우는 일을 줄이기 위해 다음을 분리합니다.

- 백업 외장 SSD
- 외장 HDD
- 추가 USB
- SD 카드

설치 시에는 가능한 한 내부 디스크와 설치 USB만 남깁니다.

## 2부. 맥에서 설치 USB 만들기

### 06. USB 확인과 ISO 다운로드

#### 목표

설치 USB를 식별하고 공식 ISO를 받을 수 있습니다.

#### 06-1. 디스크 유틸리티에서 확인

1. USB 연결
2. Spotlight에서 `디스크 유틸리티` 검색
3. `보기 → 모든 기기 보기`
4. 왼쪽 `외장` 항목 확인
5. USB 최상위 장치 선택
6. 이름·용량·연결 방식 확인

이번 확인값:

- `NO NAME`
- 약 31.44GB
- USB
- FAT32

기존 사용 공간이 있었으므로 필요한 파일 유무를 먼저 확인했습니다.

#### 06-2. 미리 포맷해야 하나요?

이번 방식에서는 별도 포맷이 필수가 아닙니다.

기록 도구가 ISO를 쓰면서 USB 내용을 덮어씁니다.

필요한 것은:

- 기존 파일 백업
- 정확한 대상 선택
- 이미지 기록

#### 06-3. 명령으로 확인

맥 터미널:

```bash
diskutil list external physical
```

이번 대화에서는 AI 실행 환경이 macOS 디스크 관리 프레임워크에 접근하지 못했습니다.

이 접근 실패를 USB 고장으로 판단하지 않았습니다.

실제 확인은 디스크 유틸리티 화면으로 진행했습니다.

`disk5s1` 같은 번호는 다시 연결하면 달라질 수 있습니다.

교안의 번호를 그대로 사용하면 안 됩니다.

#### 06-4. 공식 ISO 받기

공식 사이트:

<a href="https://omarchy.org/" target="_blank" rel="noopener">https://omarchy.org/</a>

이번 파일:

```text
omarchy-4.0.4.iso
```

새 실습에서는 현재 공식 배포 버전을 확인합니다.

#### 06-5. 맥의 칩과 ISO 대상 구분

기록 프로그램:

- 맥북에서 실행하므로 macOS용
- 칩별 구분이 있으면 Apple Silicon용

운영체제 이미지:

- 실제 설치 대상 HP PC 기준

**M1 맥에서 USB를 만든다고 HP용 ISO를 ARM용으로 바꾸지 않습니다.**

#### 06-6. 다운로드 완료 확인

- `.iso` 파일인가?
- 다운로드 중 임시 파일은 아닌가?
- 다운로드가 끝났는가?
- 공식 파일 크기와 크게 다르지 않은가?

크기만으로 정상 파일임이 증명되지는 않습니다.

#### 06-7. SHA-256 비교

맥 터미널:

```bash
shasum -a 256 ~/Downloads/omarchy-4.0.4.iso
```

파일명이 다르면 수정합니다.

경로 입력이 어렵다면:

1. `shasum -a 256 ` 입력
2. 뒤의 공백 확인
3. ISO를 터미널에 끌어놓기
4. Enter

공식 SHA-256 값과 비교합니다.

- 일치: 공식 확인값과 같음
- 불일치: 기록 중단 후 출처·다운로드 재확인

[실습 기록]

방법은 안내했지만 실제 출력값을 대조한 결과는 대화에 남지 않았습니다.

### 08. Raspberry Pi Imager로 USB 제작

#### 08-1. 왜 이 도구를 쓰나요?

`Use custom` 기능으로 사용자 지정 이미지를 기록할 수 있기 때문입니다.

이번에는 Raspberry Pi OS가 아니라 Omarchy ISO를 기록했습니다.

#### 08-2. 설치

공식 다운로드:

<a href="https://www.raspberrypi.com/software/" target="_blank" rel="noopener">https://www.raspberrypi.com/software/</a>

1. macOS용 다운로드
2. 응용 프로그램 폴더에 설치
3. 실행

[실습 확인]

사용 버전: 2.0.12

#### 08-3. 기기 선택

1. 기기 목록 아래로 이동
2. `No filtering`
3. `NEXT`

특정 Raspberry Pi 모델에 맞춰 OS 목록을 제한하지 않습니다.

#### 08-4. OS 선택

1. `Use custom`
2. `omarchy-4.0.4.iso`
3. `NEXT`

실습 화면에는 약 6.2GB 로컬 이미지가 표시됐습니다.

크기만 보이는 화면에서는 파일명까지 확인할 수 없으므로 선택한 이름도 확인합니다.

#### 08-5. USB 선택

이번 대상:

- 약 31.5GB
- `NO NAME`
- USB 장치

확인:

- [ ] 설치용 USB인가?
- [ ] 이름·용량이 맞는가?
- [ ] 백업 디스크가 아닌가?
- [ ] 맥 내부 저장장치가 아닌가?

`Exclude system drives` 옵션은 유지합니다.

다만 안전장치가 있어도 직접 확인은 필요합니다.

**Macintosh HD를 선택하지 않습니다.**

#### 08-6. 사용자 설정

Raspberry Pi용 계정·무선 설정을 묻는다면 적용하지 않습니다.

Omarchy ISO 기록이 목적입니다.

버전에 따라 해당 단계가 없을 수 있습니다.

#### 08-7. 쓰기

1. 원본 ISO 재확인
2. 대상 USB 재확인
3. 삭제 경고 확인
4. 기록 시작
5. 필요한 관리자 인증
6. 검증 완료까지 대기

- 맥 종료 금지
- 어댑터 움직임 주의
- 다른 디스크 작업 피하기

#### 08-8. 완료 확인

[실습 확인]

- Omarchy 이미지
- 대상 USB
- `Done`
- 안전하게 제거 가능

이후 HP에서 실제 USB 부팅에도 성공했습니다.

#### 08-9. 읽을 수 없는 디스크 알림

기록 후 맥에서 “읽을 수 없는 디스크” 알림이 나타났습니다.

설치 USB의 구성을 macOS가 일반 볼륨처럼 읽지 못할 수 있습니다.

이번에는:

- `Initialize` 누르지 않음
- 완료 확인
- `Eject`
- 안전하게 분리

모든 읽기 오류가 정상이라는 뜻은 아닙니다.

이번 판단은 제작 완료 화면과 실제 부팅 성공을 함께 근거로 합니다.

## 3부. HP 노트북에 Omarchy 설치하기

### 09. BIOS·UEFI와 USB 부팅

#### 09-1. USB 옮기기

1. 맥에서 안전하게 추출
2. HP 종료
3. 전원 어댑터 연결
4. USB 연결
5. 전원 켜기

#### 09-2. HP 시작 메뉴

전원을 켜자마자 `Esc`를 반복합니다.

대표 항목:

- `F9`: Boot Device Options
- `F10`: BIOS Setup

화면은 BIOS 버전에 따라 다를 수 있습니다.

#### 09-3. BIOS 확인

```text
Esc → F10
```

`Boot Options`를 찾습니다.

가능한 위치:

- System Configuration
- Advanced
- Security 관련 메뉴

확인:

- USB Boot: Enabled
- Secure Boot: 설치 환경에 맞게 해제
- UEFI 유지

USB가 안 보인다고 Legacy부터 켜지 않습니다.

#### 09-4. TPM 주의

Omarchy 공식 설치 문서는 Secure Boot 및/또는 TPM 해제를 안내합니다.

하지만 다음은 다릅니다.

- Secure Boot 끄기
- TPM 기능 끄기
- TPM 키 초기화

기존 암호화와 복구 키를 확인하지 않고 `Clear TPM`·`Reset TPM`을 선택하지 않습니다.

#### 09-5. 변경 확인 코드

HP가 화면에 코드를 표시하면 해당 코드를 입력하고 Enter로 승인합니다.

입력칸이나 글자가 보이지 않을 수도 있습니다.

#### 09-6. USB 일회성 부팅

1. 설정 저장
2. 재시작
3. `Esc → F9`
4. UEFI USB 선택
5. Enter

#### 09-7. 사진을 못 보내는 경우

실습에서는 BIOS 사진을 보낼 수 없는 상황도 있었습니다.

이때는 다음을 글로 전달했습니다.

- 화면 제목
- 메뉴 이름
- 현재 값
- 마지막으로 누른 키
- 오류 문구

예:

```text
Boot Options가 보입니다.
Secure Boot는 Enabled입니다.
```

“안 됩니다”보다 실제 문구가 문제 해결에 도움이 됩니다.

### 10. 키보드·계정·설치 디스크 선택

#### 10-1. Press return

Press return
```

이 단계까지 USB 부팅이 진행된 것입니다.

#### 10-2. Keyboard layout

한글 항목이 보이지 않아 질문이 있었습니다.

us
```

를 선택하도록 안내했습니다.

이유:

- 한글 입력기는 설치 후 구성

#### 10-3. 사용자 계정

[권장]

- 사용자 이름은 영문
- 암호는 초기 부팅에서도 입력 가능한 구성

실제 보고:

```text
/dev/nvme0n1 — 238.5GB
```

약 32GB 설치 USB와 구분되는 내부 NVMe 디스크였습니다.

확인 순서:

1. 장치 경로
2. 모델·용량
3. 내부·외장 구분
4. 백업 여부
5. 선택

`/dev/sda`가 무조건 USB라는 식으로 외우지 않습니다.

다른 컴퓨터에서는 내부 디스크가 `/dev/sda`일 수도 있습니다.

#### 10-5. 전체 디스크 설치

이번 목적은 Windows를 지우고 설치하는 것이었습니다.

설치 방식 선택 시:

```text
Full-disk install
```

최종 확인:

- [ ] 내부 디스크가 맞다.
- [ ] 용량이 맞다.
- [ ] USB가 아니다.
- [ ] 백업을 마쳤다.
- [ ] Windows와 파일 삭제를 이해했다.

[공식 문서]

전체 디스크 설치는 선택한 디스크를 지우며 기본적으로 암호화를 사용합니다.

#### 10-6. 설치 중

- 전원 연결 유지
- USB 분리 금지
- 강제 종료 금지
- 중복 설치 금지
- 오류 문구 기록

공식 문서의 빠른 설치 시간을 이 HP의 실측 시간처럼 쓰지 않습니다.

#### 10-7. 완료 후

### 11. GRUB 화면에서 정상 부팅까지

#### 11-1. 실제 증상

사용자는 다음 문구를 보고했습니다.

```text
GNU GRUB
Minimal BASH-like line editing is supported.
...
grub>
```

처음 전달한 `grab>`는 추가 문구를 통해 GRUB 화면으로 파악했습니다.

#### 11-2. 바로 실패라고 판단하지 않습니다

이 화면만으로 다음은 확정할 수 없습니다.

- 설치 실패
- 디스크 고장
- USB 손상
- 재설치 필요

정확한 원인은 추가 확인이 필요합니다.

#### 11-3. 진행한 접근

1. 설치 완료 후 재부팅인지 확인
2. 완료 상태라면 USB 분리
3. HP 부팅 메뉴 진입
4. 실제 부팅 항목 확인
5. Omarchy 항목으로 진행

보고된 항목:

```text
Omarchy Bootloader
Omarchy
```

이후:

```text
Omarchy
  → linux-omarchy
```

해당 경로에서 Enter로 진행했습니다.

#### 11-4. 결과

[실습 확인]

사용자 보고:

```text
바탕화면 나왔습니다.
```

이후:

```text
정상 부팅됩니다.
```

USB 없이 정상 부팅을 확인했습니다.

#### 11-5. 확정하지 않은 것

- GRUB가 먼저 실행된 정확한 원인
- GRUB가 있던 저장장치
- 펌웨어 부팅 순서의 실제 변경 여부
- EFI 항목의 영구 기본값 설정 여부

**GRUB 명령으로 복구했다고 쓰지 않습니다.**

복구 명령을 실행한 기록은 없습니다.

#### 11-6. 같은 문제가 반복되면

수집할 정보:

- USB 연결 여부
- 설치 완료 확인
- F9 목록
- 선택한 항목
- 오류 문구
- 특정 항목을 수동 선택해야만 켜지는지

디스크를 다시 지우기 전에 부팅 경로를 진단합니다.

## 4부. Omarchy를 편하게 사용하기

### 13. 한글 입력과 한/영 키

#### 13-1. 배열·입력기·표시 언어

세 가지를 구분합니다.

```text
키보드 배열
≠ 한글 입력기
≠ 메뉴 표시 언어
```

영어 메뉴를 유지하면서 한글을 입력할 수 있습니다.

#### 13-2. 입력기 설치

인터넷 연결 후 **Omarchy 터미널**에서:

```bash
sudo pacman -S --needed fcitx5-hangul fcitx5-configtool
```

의미:

- `sudo`: 관리자 권한
- `pacman`: 패키지 관리
- `-S`: 설치
- `--needed`: 불필요한 재설치 방지
- `fcitx5-hangul`: 한글 입력 엔진
- `fcitx5-configtool`: 설정 도구

비밀번호가 보이지 않아도 정상일 수 있습니다.

다른 업데이트와 동시에 실행하지 않습니다.

저장소 오류가 난다고 `pacman -Sy`만 단독 실행하는 방식으로 우회하지 않습니다.

#### 13-3. 설정 창

```bash
fcitx5-configtool
```

진행:

1. Input Method
2. `+` 또는 Add
3. Only Show Current Language 체크 해제
4. Hangul 검색
5. 추가
6. Keyboard - English (US) 유지
7. Apply

#### 13-4. 전환키

Global Options의 Trigger Input Method에서 전환키를 설정합니다.

처음에는:

```text
Shift + Space
```

를 안내했습니다.

#### 13-5. 실제 시험

브라우저 입력란에서 전환 후:

```text
gksrmf
```

입력 결과:

```text
한글
```

[실습 확인]

사용자가 “한글이 입력이 됩니다”라고 보고했습니다.

#### 13-6. 한/영 전용 키

1. 설정 도구 실행
2. Global Options
3. Trigger Input Method
4. 새 단축키 추가
5. 실제 한/영 키 누르기
6. Apply
7. 입력란 시험

표시 이름은 기기마다 다를 수 있습니다.

예:

- Hangul
- Alt_R
- 다른 키 조합

[실습 확인]

설정 작업을 마쳤다는 보고는 있습니다.

다만 실제 등록 이름·모든 앱 동작·재부팅 후 유지까지 세부 기록이 남은 것은 아닙니다.

#### 13-7. 키가 안 먹으면

- 입력칸에 초점이 있는가?
- Shift + Space는 되는가?
- 어떤 키 이름으로 등록됐는가?
- 다른 단축키가 먼저 처리하는가?
- 특정 앱에서만 안 되는가?
- Windows VM에서만 안 되는가?

오른쪽 Alt를 다른 기능에 배정했다면 충돌을 확인합니다.

#### 13-8. 이미 된다면 더 바꾸지 않습니다

한글이 잘 되는데 다음을 무작정 추가하지 않습니다.

- 중복 입력기
- 중복 자동 실행
- 전역 환경변수 덮어쓰기
- 오래된 X11 전용 키 재설정

특정 앱만 안 되면 그 앱부터 확인합니다.

#### 13-9. 네모 글자는 다른 문제일 수 있습니다

- 조합 안 됨: 입력기 가능성
- 조합되지만 네모: 글꼴 가능성

[선택 조치, 이번 실습 미실행]

```bash
sudo pacman -S --needed noto-fonts-cjk
```

필요할 때 글꼴 설치를 검토합니다.

### 14. 창 선택·이동·배치·닫기

#### 14-1. 실제 불편했던 장면

입력기 설정을 터미널에서 실행하자:

```text
왼쪽: 터미널
오른쪽: 설정 창
```

으로 나뉘었습니다.

오른쪽 설정 창이 좁아 잘 보이지 않았습니다.

#### 14-2. 가장 안전한 해결

1. 오른쪽 설정 창 클릭
2. `Super + F`
3. 전체화면에서 작업
4. 다시 `Super + F`

터미널을 닫지 않아도 됩니다.

#### 14-3. 터미널을 바로 닫지 않은 이유

터미널에서 실행한 프로그램은 터미널 종료의 영향을 받을 수 있습니다.

따라서 설정 작업 중에는 전체화면 전환이 안전한 대안이었습니다.

#### 14-4. 초점 이동과 위치 이동

```text
Super + 방향키
```

입력받는 창만 바꿉니다.

```text
Super + Shift + 방향키
```

창 위치를 바꿉니다.

둘을 구분하면 실수가 줄어듭니다.

#### 14-5. 닫기

```text
Super + Q
```

또는:

```text
Super + W
```

먼저 닫을 창에 초점을 줍니다.

저장하지 않은 내용이 있으면 저장합니다.

#### 14-6. Super + Q가 안 됐던 사례

사용자는 닫히지 않는다고 보고했습니다.

대안:

- Super + W
- 설정 창 전체화면

원인은 확인하지 못했습니다.

초점·키 등록 대기 상태·단축키 설정 등을 가능성으로만 남깁니다.

#### 14-7. Ctrl + D

터미널 셸이 입력 대기 중이면 종료에 사용할 수 있습니다.

하지만 다른 프로그램이 실행 중이면 다르게 동작할 수 있습니다.

키 등록 창에서는 단축키로 기록될 수도 있습니다.

만능 종료 키로 가르치지 않습니다.

### 15. 자주 사용하는 단축키

> 공식 기본값을 중심으로 정리했습니다.
> 현재 설치 환경은 `Super + K`로 확인합니다.

#### 15-1. 처음 외울 8개

- `Super + Space`: 메뉴
- `Super + Enter`: 터미널
- `Super + Shift + Enter`: 브라우저
- `Super + Shift + F`: 파일 관리자
- `Super + 방향키`: 창 선택
- `Super + Shift + 방향키`: 창 위치 교환
- `Super + F`: 전체화면
- `Super + K`: 단축키 안내

#### 15-2. 창 관리

- `Super + Q` 또는 `Super + W`: 현재 창 닫기
- `Super + J`: 가로·세로 배치 전환
- `Super + T`: 타일링·떠 있는 창 전환
- `Alt + Tab`: 창 사이 전환
- `Super + 마우스 왼쪽 드래그`: 창 이동
- `Super + 마우스 오른쪽 드래그`: 크기 조절

#### 15-3. 작업 공간

- `Super + 1`: 1번 공간
- `Super + 2`: 2번 공간
- `Super + Shift + 2`: 현재 창을 2번 공간으로 이동
- `Super + Tab`: 다음 공간
- `Super + Shift + Tab`: 이전 공간

#### 15-4. 복사·붙여넣기

- `Super + C`: 복사
- `Super + V`: 붙여넣기
- `Super + X`: 잘라내기, 터미널 제외
- `Super + Ctrl + V`: 클립보드 기록

일반 Linux 터미널에서:

- `Ctrl + Shift + C`: 복사
- `Ctrl + Shift + V`: 붙여넣기

`Ctrl + C`는 터미널 작업을 중단할 수 있습니다.

#### 15-5. 캡처·공유

- `Print Screen`: 캡처
- `Alt + Print Screen`: 녹화 시작·종료
- `Super + Ctrl + C`: 캡처 메뉴
- `Super + Ctrl + Print Screen`: 글자 추출
- `Super + Ctrl + S`: 공유 메뉴

#### 15-6. 알림

- `Super + ,`: 최근 알림 닫기
- `Super + Shift + ,`: 모든 알림 닫기
- `Super + Shift + Alt + ,`: 알림 기록
- `Super + Ctrl + ,`: 알림 억제 전환

#### 15-7. 리마인더

- `Super + Ctrl + R`: 만들기
- `Super + Ctrl + Alt + R`: 목록
- `Super + Ctrl + Shift + R`: 모두 지우기

**마지막 키는 개별 삭제 메뉴가 아닙니다.**

#### 15-8. 시스템

- `Super + Escape`: 시스템 메뉴
- `Super + Ctrl + L`: 잠금

현재 공식 문서상 Omarchy 바탕화면의:

```text
Ctrl + Alt + Delete
```

는 **모든 창 닫기**입니다.

무조건 재부팅 키로 생각하지 않습니다.

### 17. LocalSend로 맥북과 파일 주고받기

학교·기관에서는 담당자의 정책 확인이 필요할 수 있습니다.

#### 17-7. 성공 기준

- 파일이 열리는가?

## 5부. Windows 가상머신 사용하기

### 20. Windows VM 설치와 실행

#### 20-1. 운영체제를 다시 바꾸는 것이 아닙니다

이번 구성:

```text
HP 하드웨어
└─ Omarchy
   └─ Windows VM
```

Omarchy를 지우고 Windows로 복귀하는 작업이 아닙니다.

#### 20-2. 용도와 제한

적합한 예:

- Office 등 업무 앱
- Windows 전용 프로그램 시험
- 운영체제 비교 학습

기본 구성에 GPU 패스스루가 없어 고사양 게임·영상 편집용으로 기대하지 않습니다.

특정 학교 프로그램·보안 모듈의 VM 호환성도 별도 확인합니다.

#### 20-3. 라이선스

[공식 문서]

- Windows 11 Pro
- 설치 직후 미인증
- 사용에 맞는 라이선스 필요

기존 노트북 OEM 키가 VM에서도 자동 인증된다고 가정하지 않습니다.

제품 키는 공개하지 않습니다.

#### 20-4. 자원 확인

Omarchy 터미널:

```bash
free -h
nproc
df -h ~
ls -l /dev/kvm
```

확인:

- RAM
- 논리 CPU 수
- 여유 공간
- KVM 장치 존재

`/dev/kvm`이 없다고 CPU 미지원으로 즉시 단정하지 않습니다.

BIOS와 실행 환경도 확인합니다.

#### 20-5. 디스크 공간

공식 문서는:

- 가상 디스크 64GB 이상을 합리적 출발점으로 안내
- 이미지용 추가 공간 약 10GB 안내

업데이트·앱·파일을 위한 여유도 필요합니다.

이번 VM의 실제 RAM·CPU·디스크 할당값은 대화에 기록되지 않았으므로 임의로 채우지 않습니다.

#### 20-6. 설치

```text
Super + Space
→ Install
→ Windows
```

설치 질문:

- RAM
- CPU
- 디스크
- Windows 계정
- 비밀번호

#### 20-7. 취소 후 메뉴에서 사라짐

[실습 확인]

Windows 설치를 취소한 뒤 Install 메뉴에서 사라졌다는 보고가 있었습니다.

안내한 재진입:

```bash
omarchy-windows-vm install
```

이 명령은 설정을 다시 묻거나 구성을 변경할 수 있으므로 화면을 읽습니다.

기존 데이터가 있다면 먼저 백업합니다.

메뉴가 사라진 정확한 원인은 확인하지 못했습니다.

바로 Remove나 디스크 삭제로 진행하지 않았습니다.

#### 20-8. 설치 화면 주소

공식 로컬 웹 콘솔:

```text
http://127.0.0.1:8006
```

HP 자신을 뜻합니다.

맥북에서 같은 주소를 연다고 HP에 연결되지 않습니다.

#### 20-9. 로그인 종류

##### Omarchy 관리자 암호

```text
[sudo] password for ...
```

Omarchy 비밀번호입니다.

##### 웹 콘솔

VM 설치 때 설정한 계정으로 인증합니다.

##### Windows 로그인

Windows 계정으로 로그인합니다.

##### 디스크 암호화 해제

Omarchy 부팅 과정의 암호 화면일 수 있습니다.

화면 제목을 확인하고 비밀번호를 혼동하지 않습니다.

#### 20-10. 실행

```text
Super + Space
→ Windows 검색
→ 실행
```

또는:

```bash
omarchy windows vm launch
```

공식 안내상 시작에 15~30초 정도 걸릴 수 있습니다.

반복 클릭하지 않고 기다립니다.

#### 20-11. 상태·종료

```bash
omarchy windows vm status
```

```bash
omarchy windows vm stop
```

먼저 Windows에서 작업을 저장합니다.

#### 20-12. 기본 방식과 사용자용 방식 구분

현재 공식 문서는 기본 RDP 창을 닫으면 VM도 종료된다고 설명합니다.

하지만 이번 추가 기록에서는 창이 닫혀도 VM이 유지되도록 사용자용 실행기를 적용했습니다.

따라서 **창을 닫았다고 VM까지 꺼졌다고 생각하지 않습니다.**

공식 유지 실행 옵션:

```bash
omarchy windows vm launch --keep-alive
```

사용자용 바로가기와 같은 동작인지까지는 별도 확인합니다.

### 21. 시작 실패·설치 중단·권한 문제 안정화

#### 자료의 범위

[추가 기록]

이 장은 2026년 10월 14~15일 당시 작업을 복원한 첨부 자료에 근거합니다.

현재 상태를 새로 검사한 결과가 아닙니다.

#### 21-1. 시작 실패

증상:

```text
Failed to start Windows VM
```

함께 나타난 현상:

- 원격 화면 없음
- 웹 접속 실패
- ERR_CONNECTION_REFUSED

Docker 서비스가 꺼진 상태도 있었지만 이것만으로 전체 실패를 설명할 수는 없었습니다.

#### 21-2. 단계별로 나눠 봅니다

```text
Docker 실행
→ 시작 전 검사
→ VM 실행
→ Windows 부팅
→ 웹·원격 화면 연결
```

어느 단계가 실패했는지 확인합니다.

#### 21-3. 공유 폴더 권한 충돌

대상:

```text
~/Windows
```

첨부 기록에 따르면 권한이:

```text
2700
```

이 됐고, 당시 실행기는 정확히:

```text
700
```

을 요구했습니다.

앞의 `2`는 setgid 속성입니다.

setgid 자체가 언제나 잘못인 것은 아닙니다.

당시 실행기의 엄격한 요구와 충돌한 것이 핵심입니다.

#### 21-4. 반복 원인

공유 서비스가 실행 후 권한을 다시 바꿨다고 기록돼 있습니다.

```text
권한 정리
→ VM 실행
→ 공유 서비스가 변경
→ 다음 시작 실패
```

당시 대응:

- setgid 제거
- 실행 전 700으로 정리
- 사용자용 실행기에 포함

이 교안에서는 원본 코드를 확인하지 않은 자동 수정 명령을 추측해 제시하지 않습니다.

특히 다음은 피합니다.

- 무조건 777로 열기
- 홈 전체 재귀 권한 변경
- 보안 검사 삭제
- 다른 폴더까지 일괄 수정

#### 21-5. 브라우저의 과거 오류

```text
ERR_CONNECTION_REFUSED
```

는 접속 시점에 서버가 연결을 받아주지 않았다는 표시입니다.

첨부 기록에서는 꺼진 VM에 접속했을 때의 화면이 남아 있었습니다.

서버가 다시 응답한 뒤 새로고침해 확인했습니다.

과거 오류 화면과 현재 VM 상태를 구분합니다.

#### 21-6. 원격 연결 실패가 VM 종료로 이어짐

기존 실행 경로:

```text
원격 연결 실패·종료
→ VM 종료
```

설치 중 연결 문제로 Windows 설치도 중단됐습니다.

VM은 가상 컴퓨터이고 원격 창은 화면 연결입니다.

둘의 수명을 분리할 필요가 있었습니다.

#### 21-7. 재설치처럼 보인 현상

설치 완료 표식 전 종료되면 다음 시작에서 설치 디스크 준비가 다시 진행됐다고 기록돼 있습니다.

모든 반복 설치 화면이 이 원인이라는 뜻은 아닙니다.

#### 21-8. 사용자용 실행기

Windows 바로가기가 `launch.py` 실행기를 호출하도록 바꿨다고 기록돼 있습니다.

역할:

1. 공유 폴더 권한 정리
2. VM 시작
3. 원격 연결
4. 창 종료 후 VM 유지

공식 명령을 직접 실행하면 같은 전처리를 거치는지 확인해야 합니다.

#### 21-9. 84%에서 멈춘 것처럼 보임

첫 단계 진행률이 84%에 한동안 머물렀지만 디스크 작업은 계속됐습니다.

이후:

- 자동 재부팅
- Windows Boot Manager 부팅
- 후속 설치·사용자 설정
- Windows 11 바탕화면

을 확인했다고 기록돼 있습니다.

당시 기록에서 메모리 부족·디스크 I/O 오류는 확인되지 않았습니다.

진행률 숫자만으로 강제 종료하지 않습니다.

반대로 모든 정체를 정상이라고 판단하지도 않습니다.

#### 21-10. 설치 보존 확인

시스템 디스크에 표식을 저장하고 재부팅 전후 같은 표식인지 확인했습니다.

목적:

- 같은 디스크인가?
- 설치가 유지되는가?
- 빈 디스크로 다시 시작한 것은 아닌가?

같은 표식이 유지된다고 개인 파일 전체의 무결성이나 백업까지 증명되는 것은 아닙니다.

먼저 구분합니다.

- 화면 배율이 큰가?

시스템 메뉴에서 종료·재시작을 선택합니다.

VM을 유지하도록 구성했다면 먼저 종료 상태를 확인합니다.

#### 26-1. 오래된 노트북을 개발용으로 확장하기

Omarchy는 일상 작업뿐 아니라 개발 환경으로도 활용할 수 있습니다.

커뮤니티 프로젝트를 활용하면 Linux에서 Apple 기기용 앱을 만드는 환경 구축에도 도전할 수 있습니다.

프로젝트:

<a href="https://github.com/joshuaswarren/omarchy-apple-dev" target="_blank" rel="noopener">https://github.com/joshuaswarren/omarchy-apple-dev</a>

이것은 Apple 공식 Xcode 자체가 아닙니다.

모든 iOS 앱과 기능을 지원하거나 Xcode를 완전히 대체한다는 뜻도 아닙니다.

#### 26-2. 가능한 학습 흐름

프로젝트 문서:

```text
개발 도구
→ SDK
→ 예제 생성
→ 빌드
→ 서명·기기 연결
→ iPhone 설치
→ 실제 동작 확인
```

Swift·SwiftUI·Flutter 등을 다룹니다.

작성자는 실제 기기 실행과 App Store Connect 처리 사례를 공개합니다.

이는 프로젝트의 검증 기록이지 이번 HP의 재현 결과는 아닙니다.

#### 26-3. 준비

- Omarchy 컴퓨터
- 인터넷·저장공간
- 터미널 기초
- 백업
- 지원되는 iPhone·iOS
- USB 데이터 케이블
- Apple 계정
- 서명·기기 설정

TestFlight·App Store 배포는 유료 멤버십 등 별도 요건이 있습니다.

HP에서의 속도와 쾌적함은 사양 확인 후 판단합니다.

#### 26-4. full 모드

Xcode 배포 파일에서 필요한 SDK를 가져오는 방식입니다.

- Linux에서 Xcode 앱을 실행하는 것이 아님
- Swift·SDK 버전 맞추기 필요
- Apple 다운로드·사용 조건 확인
- 지원 범위가 더 넓은 경로로 우선 검토 가능

#### 26-5. no-xcode 모드

Xcode 배포 파일을 받지 않는 실험적 경로입니다.

지원 범위가 제한돼 있습니다.

검증 상태도 나뉩니다.

- 실제 기기 실행
- 빌드만 확인
- 미검증
- 미지원

“Xcode 없이 모든 앱 개발 가능”으로 설명하지 않습니다.

#### 26-6. 문서 읽기 순서

1. README
2. GETTING-STARTED
3. TEST-MATRIX
4. FINDINGS
5. 현재 Issues

버전별 요구사항은 달라질 수 있습니다.

#### 26-7. 구축 흐름 맛보기

> 필수 실습이 아닙니다.
> 설치 스크립트의 변경 범위를 검토하고 백업한 뒤 실행합니다.

프로젝트 README의 기본 흐름:

```bash
git clone https://github.com/joshuaswarren/omarchy-apple-dev
cd omarchy-apple-dev
./install-toolchain.sh
```

설치 중 SDK 안내를 따라야 합니다.

실행이 끝났다고 완료가 아닙니다.

확인 예:

```bash
swift sdk list
```

프로젝트는 `darwin` 등록 확인을 안내합니다.

예제 빌드:

```bash
xtool new HelloOmarchy
cd HelloOmarchy
xtool dev build
```

실제 기기 실행은 추가 인증·서명·USB 연결이 필요합니다.

#### 26-9. 제한

- 기존 Xcode 프로젝트가 모두 그대로 되는 것은 아님
- full·no-xcode 지원 차이
- Flutter hot reload·시뮬레이터·플러그인 제약
- iOS 버전별 연결 차이
- VALID와 심사 승인·출시 완료는 다름

채팅·공개 저장소·교안에 넣지 않습니다.

#### 26-11. 맥북과 역할 분담

- 맥북: Xcode·시뮬레이터·기준 빌드·최종 검증
- HP: Linux 환경 구축·빌드 실험
- iPhone: 실제 동작

맥북 환경을 없애고 모두 대체할 필요는 없습니다.

### 29. 문제 해결 빠른 찾기

#### USB가 안 보입니다

확인:

- 연결·어댑터
- 디스크 유틸리티의 모든 기기
- 외장 장치 이름·용량

AI 조회 실패를 USB 고장으로 단정하지 않습니다.

#### Etcher에서 requestMetadata 오류

- 앱 종료·정상 위치 실행
- 파일 재선택
- 반복 시 대체 도구
- 이번에는 Imager로 완료

#### Imager에 Raspberry Pi 목록만 나옵니다

- 아래의 No filtering
- OS에서 Use custom
- Omarchy ISO

#### 맥이 기록 USB를 읽지 못합니다

- 기록 완료 여부 확인
- 초기화 금지
- 안전하게 추출
- 실제 부팅 확인

#### USB 부팅이 안 됩니다

- HP Esc→F9
- UEFI USB
- Secure Boot·USB Boot
- 기록 완료 여부
- 다른 기기 메뉴와 혼동하지 않기

#### 설치 디스크가 헷갈립니다

- 이름·용량·내부/외장 확인
- 이번 238.5GB NVMe는 사례일 뿐
- 번호만 외우지 않기

#### grub>가 나옵니다

- 설치 완료 여부
- USB 연결
- 실제 부팅 목록
- Omarchy 항목
- 즉시 재설치하지 않기

#### 한글이 안 됩니다

- Omarchy인가 Windows인가?
- 해당 입력기 설치?
- 전환 상태?
- 실제 입력란 초점?
- 앱별 차이?

#### 창이 좁습니다

- 해당 창 클릭
- Super+F
- 터미널을 닫기 전 실행 관계 확인

#### 창 닫기가 안 됩니다

- 초점
- 키 등록 대기 상태
- Super+K
- Super+W 대안
- 원인 미확인 상태를 단정하지 않기

#### Windows 시작 실패

- Docker
- 시작 전 검사
- 공유 폴더 권한
- VM 실행
- 원격 연결 순서로 분리

#### ERR_CONNECTION_REFUSED

- 현재 VM 상태
- 서버 대기
- 새로고침
- 과거 오류 화면인지 확인

#### Windows 설치가 반복되는 것 같습니다

- 완료 전 종료 여부
- 실행기 정책
- 설치 상태·보존 확인
- 바로 디스크 삭제하지 않기

#### 진행률 84%가 안 바뀝니다

- 디스크 작업·오류·VM 상태 확인
- 이번에는 이후 정상 진행
- 모든 정체를 정상으로 일반화 금지

#### Windows 한영 키가 안 됩니다

- 마우스 A→가
- 메모장 직접 입력
- 입력 도우미
- 원격 전달
- 호스트 키 충돌
- 재부팅 후 비교

#### LocalSend 기기가 안 보입니다

- 앱 실행
- 같은 네트워크
- 수신 승인
- 게스트 Wi-Fi·기관 정책·VPN·방화벽

## 마무리: 설치보다 중요한 것은 실제로 써보는 과정입니다

이번 경험은 운영체제를 한 번 설치하는 데서 끝나지 않았습니다.

- 맥북과 HP의 역할을 구분했습니다.

- 한글 입력과 창 조작을 익혔습니다.
- Linux 안에 Windows를 추가했습니다.
- 화면 연결과 VM 실행을 구분했습니다.
- 설정이 등록됐는지보다 실제로 동작하는지 확인했습니다.
- 재부팅 후 유지까지 확인하는 검증의 중요성을 배웠습니다.

앞으로도 다음 다섯 가지를 남깁니다.

1. 무엇을 하려 했는가?
2. 어떤 화면과 오류를 만났는가?
3. 무엇을 바꿨는가?
4. 실제로 무엇이 확인됐는가?
5. 아직 무엇을 모르는가?
