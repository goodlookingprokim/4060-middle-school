# 2026년 5월 10일(일) Hermes 서울 밋업 학습 자료를 다시 본 기록

어제 모임이 끝난 뒤 다시 들여다보게 된 자료가 하나 있었습니다. [Hermes Meetup 전사형 학습 자료](https://hermes-agent-seoul-meetup-learning.vercel.app/)입니다. 이런 자료는 보통 발표 내용을 길게 옮겨 적는 데서 그치기 쉬운데, 이번 자료는 조금 달랐습니다. 현장의 말맛과 흐름을 살리면서도, 나중에 다시 공부하는 사람이 길을 잃지 않게 잘 정리되어 있었습니다.

## 먼저 결론

- 이 자료는 단순 요약본이 아니라, 현장의 소리를 다시 공부 가능한 형태로 묶어낸 페이지에 가깝습니다.
- 특히 Hermes 기능 설명을 GitHub 원문까지 대조해 확인한 흔적이 보여서, 참고 자료로서 신뢰감이 높았습니다.
- 이런 정리는 행사 당일의 열기를 지나, 나중에 다시 꺼내 읽을 수 있는 공부 자료를 만든다는 점에서 의미가 큽니다.

## 이 페이지가 좋았던 이유

페이지를 보면 먼저 추천 학습 순서가 보이고, 세션별로 무엇을 먼저 보면 좋은지 감을 잡게 해줍니다. 발표를 그대로 늘어놓기보다, 어떤 순서로 보면 이해가 이어지는지를 먼저 제안해주는 점이 좋았습니다.

또 하나 좋았던 점은 전사 품질에 대한 설명을 숨기지 않았다는 것입니다. 12개 세션 전체를 번호 순서대로 정리했고, 저확신 구간을 추가 ASR 대조로 다시 손본 뒤 최종적으로 남은 저확신 구간이 없다고 밝히고 있습니다. 이런 부분은 겉보기에는 사소해 보여도, 실제로는 자료를 믿고 읽어도 되는지 판단하게 해주는 중요한 근거가 됩니다.

## 현장의 소리를 담아낸 방식

이 페이지는 발표 내용을 매끈하게 다듬어 버리기보다, 현장에서 실제로 오간 말의 결을 어느 정도 남겨두고 있습니다. 그래서 읽는 사람도 "아, 그 자리에 이런 분위기가 있었겠구나" 하고 따라가기가 쉽습니다.

예를 들어 오리엔테이션 부분만 봐도, 단순히 Hermes Agent의 기능 목록을 나열하는 것이 아니라 커뮤니티가 어떻게 행사를 열었는지, 어떤 사람들을 모았는지, 왜 데모 위주 구성을 택했는지 같은 맥락이 함께 살아 있습니다. 이런 맥락이 있어야 도구 설명도 더 사람 일처럼 읽힙니다.

## GitHub 소스 검증까지 끝난 점이 특히 좋았습니다

이번 페이지에서 제가 특히 좋게 본 부분은, Hermes 설명을 그냥 2차 요약에 기대지 않고 GitHub 원문과 다시 맞춰봤다는 점입니다.

제가 직접 확인한 Hermes GitHub 저장소는 [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)이고, README 기준으로도 몇 가지 큰 축이 분명합니다.

- Hermes는 스스로 학습 루프를 갖춘 에이전트로 소개됩니다.
- 경험에서 스킬을 만들고, 사용 중 스킬을 개선하고, 메모리와 과거 대화를 다시 활용하는 구조를 강조합니다.
- CLI뿐 아니라 Telegram, Discord, Slack, WhatsApp, Signal 같은 게이트웨이 연결을 지원합니다.
- 크론 스케줄링, 서브에이전트, 다양한 실행 환경 같은 운영 기능도 함께 밀고 있습니다.

즉, 이 학습 자료가 다루는 핵심 축인 **스킬, 메모리, 평가, 작업 관리, 협업 흐름**이 실제 Hermes 프로젝트의 방향과 따로 놀지 않는다는 점을 GitHub 원문으로 다시 확인할 수 있었습니다. 이건 단순히 내용을 많이 모았다는 차원이 아니라, "이 설명이 실제 소스와도 맞는가"를 한 번 더 검증한 정리라는 뜻입니다.

## 이익상 파트너님께 고맙다는 마음

이런 자료는 시간만 들인다고 되는 게 아니라, 현장에서 무엇이 중요했는지를 아는 사람이 정리해야 힘이 생깁니다. 이번 페이지는 바로 그 점이 살아 있었습니다.

현장의 소리를 이렇게 다시 공부할 수 있는 형태로 남겨주신 **이익상 파트너님께 감사한 마음**을 전하고 싶습니다. 그냥 링크 하나 남긴 것이 아니라, 나중에 다시 읽는 사람도 따라갈 수 있게 맥락과 근거를 함께 묶어주셨다는 점이 특히 좋았습니다.

## 우리에게 남는 활용 포인트

이 자료는 Hermes를 이미 쓰는 사람에게도 도움이 되지만, 아직 낯선 사람에게는 더 좋은 입구가 될 수 있습니다. 무엇을 먼저 봐야 할지 순서를 제안하고, 발표 내용을 학습 포인트와 실습 과제로 바꿔놓았기 때문입니다.

이런 식의 정리는 앞으로 우리 모임 자료를 쌓을 때도 꽤 좋은 기준이 됩니다.

<ul class="note-list">
  <li>행사 기록은 단순 요약보다 다시 공부할 수 있는 구조로 남길 것</li>
  <li>도구 설명은 가능하면 원문 링크와 소스 검증 근거를 함께 둘 것</li>
  <li>현장 분위기와 실제 말의 결을 너무 매끈하게 지우지 말 것</li>
</ul>

## 남겨둘 판단

좋은 정리는 예쁘게 요약한 문서보다, **현장의 흐름을 살리면서도 다시 검증해 읽을 수 있게 만든 자료**에 더 가깝습니다. 이번 Hermes 밋업 학습 자료는 바로 그 점에서 오래 남길 만한 기록이라고 느꼈습니다.
